# 05 · 打包与分发

## 1. 一句话结论

| 产物 | 命令 | 体积 | 谁该用 |
| --- | --- | --- | --- |
| **薄包** `.deb` | `./scripts/build-deb.sh` | ~3 MB | 进发行版仓库、自己机器、系统 Qt 齐全 |
| **自带包** `.deb` | `./scripts/bundle-runtime.sh --deb` | ~120 MB | **发给家长**：目标机器什么 Qt 都没装 |
| **绿色包** `.tar.gz` | `./scripts/bundle-runtime.sh --tgz` | ~130 MB | 插 U 盘试用、离线机器、不想动系统 |

三者装的是同一个程序，区别只在「Qt 和 QtWebEngine 从哪儿来」：
薄包用系统的，后两者用包里自带的（整套塞在 `/opt/kidssafe`）。

**不要同时装薄包和自带包**（`kidssafe` 与 `kidssafe-bundled` 在
`debian/control` 里写明了 `Conflicts`）。

## 2. 为什么需要「自带」

网页小游戏不是「装个 QML 模块就能开」的普通功能：

1. `QtWebEngineQuick::initialize()` 必须在 `QGuiApplication` 之前调用 ——
   这行代码在**编译期**就决定编不编进二进制；
2. `WebGamePage.qml` 同样被编进 qrc；
3. 运行期还要能加载 `QtWebEngine` 这个 QML 模块，并且它的版本必须和
   `libQt6Core` 对得上。

于是「构建机上没有 `qt6-webengine-dev`」的后果是：打出来的包**永远**不含网页
小游戏，用户事后 `apt install qml6-module-qtwebengine` 也补不回来（二进制里
没有那段初始化）。而 deepin 25 / UOS 这类系统的源里，这个包恰好可能没有，
或者版本和 Qt 基础库对不上。

自带包把这个链条整个搬进包里，用户那边不再需要任何 `qt6-*`。

## 3. 自带包是怎么做的（`scripts/bundle-runtime.sh`）

```
dist/kidssafe-1.19.0-linux-x86_64/
├── bin/kidssafe                      主程序
├── kidssafe.sh                       启动器（设环境变量后 exec）
├── lib/*.so*                         Qt / KF6 / nss / X11 客户端库…
├── lib/qt6/plugins/                  platforms / tls / imageformats / wayland…
├── lib/qt6/qml/                      QtQuick、QtWebEngine、org/kde/{kirigami,breeze}
├── libexec/QtWebEngineProcess        Chromium 的 helper 进程
├── resources/                        icudtl.dat + *.pak
├── translations/qtwebengine_locales/ zh-CN / zh-TW / en-US
└── share/kidssafe/{playland,maker,codelab,audio}
```

关键点四个，每个都对应一个「不做就白屏」的故障：

**① 依赖靠 `ldd` 广度优先抄，不是靠手写清单。**
从 `bin/kidssafe` 出发，把依赖、依赖的依赖……一路抄进 `lib/`，插件和
`QtWebEngineProcess` 也各过一遍。手写清单一定会漏 —— 漏的那一个通常在别人的
机器上才暴露。

**② RPATH 用 `DT_RPATH`（`patchelf --force-rpath`），不是默认的 `DT_RUNPATH`。**
`DT_RUNPATH` 不传递给「依赖的依赖」：`libKF6CoreAddons.so` 找
`libQt6Core.so.6` 时不会看主程序的 RUNPATH，于是偷偷加载了系统 Qt —— 版本一混
就崩。`DT_RPATH` 是可传递的老式字段，正是这里需要的。

**③ WebEngine 的「运行期三件套」必须单独搬。**
helper 进程、`icudtl.dat` + `*.pak`、语言包都不在 `lib/` 里，`ldd` 抄不到。
漏了的表现是网页区域整块白，日志里只有一句 `Could not find QtWebEngineProcess`。

**④ 打包前必须自检。**
脚本最后做两件事：用 `patchelf --print-needed` 检查每个 ELF 的 Qt/KF6 依赖是否
都在包里（防止「构建机上系统库补齐了、到用户机器就缺」），再真跑一次
`kidssafe.sh --self-test`。不跑这一步，最常见的结局是「在我这儿是好的」。

## 4. 启动器设了哪些变量

| 变量 | 不设的后果 |
| --- | --- |
| `LD_LIBRARY_PATH` | 加载系统 Qt，和包里的 QML 混用 → 崩或白屏 |
| `QT_PLUGIN_PATH` | 找不到 `libqxcb.so`，报 `no Qt platform plugin could be initialized` |
| `QML_IMPORT_PATH` | 找不到 `QtQuick.Controls`，界面起不来 |
| `QTWEBENGINEPROCESS_PATH` | 网页区全白，`Could not find QtWebEngineProcess` |
| `QTWEBENGINE_RESOURCES_PATH` | 网页区全白，缺 ICU / pak |
| `QTWEBENGINE_LOCALES_PATH` | 界面能显示，Chromium 的右键菜单变英文 |
| `QTWEBENGINE_DISABLE_SANDBOX=1` | Chromium 起不来（见下一节） |

程序启动时会把这几个路径打进日志（`[webengine] 自带运行时 · helper: … ✓`），
缺哪个一眼能看到。

## 5. 说清楚的代价

- **沙箱关闭**。Chromium 的 setuid 沙箱要求 `chrome-sandbox` 属主是 root 且带
  4755 位；包在用户可写或可移动的目录里做不到。关掉的后果是渲染进程不再有
  独立沙箱隔离。缓解事实：网页内容随包提供（本地 HTML），不加载外部站点，
  联网只走故事服务端的接口。**但这是真实降级，不是等价替代。**
- **只带三种语言包**（zh-CN / zh-TW / en-US）。其它 locale 由 Chromium 退回 en-US。
- **不打包 glibc / libstdc++ / 显卡驱动**。它们必须和用户内核、驱动匹配，
  搬过去只会更坏；所以自带包仍要求系统是 glibc ≥ 2.34（Ubuntu 22.04 起）。
- **体积**。解压后 ~300 MB，deb 压缩后 ~120 MB。薄包只有 3 MB —— 这就是为什么
  两个包都保留：进仓库用薄的，发给家长用自带的。

## 6. 安装、升级、卸载

```sh
# 自带包
sudo apt install ./dist/kidssafe-bundled_1.19.0_amd64.deb
/opt/kidssafe/kidssafe.sh --self-test        # 装完先验一次
sudo apt remove kidssafe-bundled             # 卸（保留 ~/.config）
sudo apt purge  kidssafe-bundled             # 连配置一起卸

# 薄包
sudo apt install ./dist/kidssafe_1.19.0_amd64.deb
sudo apt remove kidssafe

# 绿色包：解压即用（写不进会话菜单，只能当窗口程序跑）
tar xf kidssafe-1.19.0-linux-x86_64.tar.gz
./kidssafe-1.19.0-linux-x86_64/kidssafe.sh --windowed
```

会话入口只由 `.deb` 提供：`/usr/share/xsessions/kidssafe.desktop` 与
`/usr/share/wayland-sessions/kidssafe-wayland.desktop`。绿色包和 AppImage
写不进这两个目录，所以登录界面里选不到 —— 这是「必须走包管理器」的根本原因，
也是本项目不建议 AppImage 的理由。

## 7. 自建 apt 源

多机部署（一个班、一个机构）时可以先建一个本地源，让家长只执行
`apt install kidssafe-bundled`。做法见 `Linux/README.md` 第七节「多机部署」。
