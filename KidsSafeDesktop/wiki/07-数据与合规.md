# 07 · 数据与合规

这一页是「对外要交的材料」和「对内要守的规矩」的汇总，每条都能追到原件。
正式提交时请直接用原件，不要用本页的转述。

## 1. 数据流向：默认不出机器

| 数据 | 存在哪 | 上不上传 |
| --- | --- | --- |
| 配置、PIN、白名单、时长 | 本机（`~/.config/kidssafe/kidssafe.conf` / 应用私有目录） | 不上传 |
| 使用时长、星星、答题记录 | 本机 | 不上传（家长后台看的是本机数据） |
| 故事 / 安全知识内容 | 随包 + 家长自建服务器 | 只读取，不回传 |
| 天气 | 本机缓存 | 只发经纬度到 Open-Meteo，不带任何身份 |
| 意见反馈 / 问卷 | 家长主动提交才发 | 提交到 `kids.siguangblog.cc`，官网有公开统计 |
| 崩溃 / 运行日志 | 本机 | 不上传，需要时让家长手动发 |

几条硬约束：

- **不注册账号也能用**。账号体系是为「一台服务器放多个家庭」准备的，不是使用前提。
- **联网能力默认关闭**。`onlineContentEnabled`（内容）与 `netplayEnabled`（联机）
  是两个独立开关，都默认关，都要家长在 PIN 后面手动打开。
- **海外归因 SDK（Singular）在国行包里连代码都没有**，不是「带了但不调用」。
  见 `Docs/Singular海外版归因接入.md`。

## 2. 隐私政策与 SDK 清单

| 文件 | 用途 |
| --- | --- |
| `Docs/隐私政策.md` | 与 App 内「隐私政策」页逐字一致，商店提交时可直接粘贴全文 |
| `Docs/第三方SDK清单.md` | 每个 SDK 的名称、提供方、用途、收集的信息、是否可关闭 |
| `Docs/账号体系.md` | 家长账号 + 配对码，一个服务器多家庭，配置按账号隔离 |

改隐私政策时**三处要同时改**：`Docs/隐私政策.md`、App 内的政策页、
官网 `/privacy.html`。漏一处就会被商店审核打回。

## 3. 儿童相关内容的两道自检

上架审核最容易问的两个点，文档里都准备了口径：

1. **激励设计**：星星不是「付费/抽奖」，是完成任务后的固定奖励，没有随机掉落。
   → `Docs/星星奖励与关爱中心.md`
2. **未成年人心理内容**：关爱中心的 6 节家长课、心情日记、呼吸放松，全部由
   公开发表的家庭教育文章归纳改写，不提供诊断或治疗建议。
   → `Docs/关爱中心-家长课素材.md`、`Docs/我的日记.md`

## 6. 签名与密钥

`Docs/签名与荣耀推送配置.md` **含 keystore 口令**，属于机密材料：
不要提交到公开仓库、不要截图外发。仓库里只有 `Signing.props.sample`，
真实的 `Signing.props` 在开发者本机。

## 7. 合规检查清单（发版前过一遍）

- [ ] 默认联网开关仍是关闭状态
- [ ] 新收集的任何字段都能在隐私政策里找到对应条目
- [ ] 儿童可见文案里没有诱导付费、没有外链
- [ ] 更新记录已写（`Docs/更新记录.md`），版本号与 `versionCode` 同步
