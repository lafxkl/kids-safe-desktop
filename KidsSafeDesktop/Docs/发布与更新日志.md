# 发布与更新日志：数据源、接口与发版流程

> 目的：让「版本号、更新说明、下载信息」只有**一处真相**，避免 App、官网、家长后台三处各写一份、互相对不上。

## 一、数据从哪里来

```
KidsSafeServer/Releases.cs          ← 唯一数据源（结构化：版本号 / versionCode / 日期 / 标题 / 标签 / 要点）
        │
        ├── GET /api/app/release          给客户端与官网取数据
        ├── GET /api/app/changelog        给「更新日志」列表
        ├── GET /api/app/update-check     给客户端判断是否需要升级
        └── 家长后台 wwwroot/index.html   登录后显示「版本与更新」卡片（读 health + release）

KidsSafeDesktop/Website/changelog.html   ← 官网展示版（同样内容，静态 HTML，商店审核可抓取）
KidsSafeDesktop/Docs/更新记录.md          ← 开发者长文版（含根因、文件路径、构建踩坑）
```

三份文案口径一致，但**受众不同**：

| 位置 | 受众 | 写法 |
|---|---|---|
| `Releases.cs` | 接口消费方 | 结构化、一句话一条，可含技术细节 |
| `Website/changelog.html` | 家长 / 商店审核 | 产品语言，讲「改了什么、对我有什么用」 |
| `Docs/更新记录.md` | 自己与协作者 | 全量记录根因、文件名、命令、踩过的坑 |

## 二、接口清单

### 1. 健康检查（含服务端自身版本）

```
GET /api/health
```

```json
{
  "ok": true,
  "server": "KidsSafeServer",
  "serverVersion": "1.2",
  "startedAt": "2026-11-04T14:18:21+00:00",
  "uptimeSeconds": 120,
  "watchVersion": 1793801901281,
  "pulseCount": 2,
  "lastPulseAt": "2026-11-04T14:20:01+00:00",
  "latestAppVersion": "1.15",
  "latestAppVersionCode": 16
}
```

`ok` 字段保持存在，老的探活脚本不受影响；新增字段用于判断「服务是不是刚重启」「配置被保存过几次」。

### 2. 最新版本

```
GET /api/app/release/latest
```

```json
{
  "ok": true,
  "channel": "stable",
  "latest": { "version": "1.15", "versionCode": 16, "date": "2026-11-04", "title": "...", "tags": ["修复"], "highlights": ["..."] },
  "downloadUrl": "",
  "releasePage": "changelog.html"
}
```

`downloadUrl` 从 `appsettings.json` 的 `Site:DownloadUrl` 读取，留空表示暂未提供公网下载；`Site:ReleasePage` 指向官网更新日志页。

### 3. 全量 / 前 N 版

```
GET /api/app/release?limit=3
GET /api/app/changelog?limit=5
```

两者都返回 `{ ok, items|history }`，`limit` 省略或为 0 时返回全部（当前 18 个版本）。

### 4. 客户端检查更新

```
GET /api/app/update-check?versionCode=12&platform=android
```

```json
{
  "ok": true,
  "currentVersionCode": 12,
  "hasUpdate": true,
  "latest": { "version": "1.15", "versionCode": 16, "date": "2026-11-04", "title": "...", "tags": ["新增"] },
  "latestHighlights": ["..."],
  "signatureChanged": false,
  "downloadUrl": "",
  "releasePage": "changelog.html"
}
```

**`signatureChanged` 是这里最要紧的字段**：v1.8（versionCode 9）更换过签名证书，低于该版本的安装包与当前包签名冲突，**不能覆盖安装，必须先卸载**。客户端拿到 `true` 时应当提示「需卸载后安装」，而不是直接触发升级。

### 5. 指定版本

```
GET /api/app/release/v1.10     # 版本号可带 v 前缀
```

找不到返回 404 `{ "ok": false, "error": "未找到该版本：v9.9" }`。

### 6. 安装包下载

```
GET /api/download/list
```

```json
{
  "ok": true,
  "latestAppVersion": "1.15",
  "latestVersionCode": 16,
  "downloadUrl": "",
  "files": [
    {
      "name": "KidsSafeDesktop-1.15.apk",
      "size": 123456789,
      "sizeText": "117.7 MB",
      "platform": "android",
      "updatedAt": "2026-11-04T14:00:00Z",
      "url": "/downloads/KidsSafeDesktop-1.15.apk",
      "sha256": "E0527093..."
    }
  ],
  "preferred": { "android": "/downloads/KidsSafeDesktop-1.15.apk", "windows": null }
}
```

数据来自扫描 `wwwroot/downloads/`（见 `Downloads.cs`），只认 apk / aab / zip / msi / exe 五种扩展名，按修改时间倒序；SHA-256 按「路径 + 修改时间」缓存，文件不变不重算。`downloadUrl` 是 `Site:DownloadUrl` 配置的外部地址，非空时下载页优先用它（应用市场 / 对象存储场景）。

配套页面：

| 地址 | 内容 |
|---|---|
| `/download.html`（短地址 `/download`） | 下载页：双平台按钮、文件大小与 SHA-256、安装步骤、最近版本 |
| `/docs.html`（短地址 `/docs`、`/server`） | 服务端说明：用途、启动、配置项、接口清单、安全须知、FAQ |

## 三、发版流程

### 一键脚本（推荐）

根目录的 `release.bat` 把机械步骤都串起来了：

```bat
release.bat 1.17 18      :: 升到 v1.17 / versionCode 18，双端出包并回填官网
release.bat              :: 用 csproj 里的当前版本重新出包
release.bat 1.17         :: 只给版本号，versionCode 自动 +1
release.bat -SkipBuild   :: 不编译，只用现有产物重新打包归位
release.bat -Clean       :: 构建前清 bin / obj
release.bat --help       :: 全部参数
```

它依次做：

1. 校验并写入 `ApplicationDisplayVersion` / `ApplicationVersion`（versionCode 必须递增，否则直接停）
2. `dotnet build -c Release` 出 Android 签名 APK 与 Windows 包
3. 复制成 `KidsSafeDesktop-<版本>.apk` / `-win.zip`
4. 把上一版安装包归档到 `D:\WorkBuddy\_release\v<旧版本>\`
5. 同步到 `KidsSafeServer\wwwroot\downloads`
6. 算文件大小（MB）与 SHA-256
7. 回填 `Website/index.html`：徽章、版本行、两个下载文件名、页脚
8. 回填 `Website/permissions.html` 的「适用版本」
9. 回填 `Website/changelog.html` 头部：当前版本、最近更新、共 N 个版本
10. 检查 `Releases.cs` 与 changelog 有没有本版条目，漏了就给黄色警告

**脚本不写内容。** `Releases.cs` 的要点、`changelog.html` 的 `<article>` 段落仍然要人写——它得说清「为什么改」，脚本猜不出来。

**顺序上建议先写这两处文字，再跑脚本。** 否则脚本会提示漏项；而且「共 N 个版本」在条目缺失时**故意不改**，避免出现「当前版本 v1.17 / 共 17 个版本」这种自相矛盾。

### 脚本不做的事（手工补）

1. **`Releases.cs`**：新版本插到 `All` 数组**最前面**（顺序即时间倒序），填 Version / VersionCode / Date / Title / Tags / Highlights。
2. **`Website/changelog.html`**：复制上一版 `<article class="rel">` 结构，改版本号、日期、code、标题、标签、要点，`id` 必须是 `v1-17` 这种「点换横线」的写法。
3. **`Docs/更新记录.md`**：写清楚改了什么、为什么改，方便下次回溯。
4. **服务端验证**（启动服务后）：
   ```bash
   curl -s http://127.0.0.1:5180/api/app/release/latest
   curl -s "http://127.0.0.1:5180/api/app/update-check?versionCode=16"
   ```

> 版本号三处必须一致：`csproj` 的 `ApplicationVersion`、`Releases.cs` 的 `VersionCode`、官网下载卡上的数字。`ApplicationVersion` 与 `VersionCode` 不一致会导致客户端「检查更新」永远提示有新版本。脚本只保证前两处里的第一处，`Releases.cs` 靠漏项检查提醒。

### 脚本本身的两个编码坑（改脚本前必读）

- **`release.bat` 必须保持纯 ASCII。** `cmd.exe` 是按**控制台代码页**（中文 Windows 是 936/GBK）解码 `.bat` 文件的，UTF-8 中文会被拆成乱码命令，连 `@echo off` 都执行不了。所以中文提示全部放在 ps1 里，bat 只做环境检查和传参。
- **`Scripts/release.ps1` 必须保存为 UTF-8 with BOM。** Windows PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 ANSI 解码，中文全乱。
- 两者都要 **CRLF 换行**，LF 在部分控制台里不会回车。

## 四、签名变更分界线

`Releases.SignatureChangedAt = 9`（即 v1.8）。若将来再次更换签名证书：

1. 把该常量改成新版本对应的 versionCode；
2. 在 `changelog.html` 该版本条目下加 `.warn` 提示块；
3. `Docs/更新记录.md` 里标注「必须先卸载」。

## 五、已验证的行为（2026-11-04）

| 检查项 | 结果 |
|---|---|
| `GET /api/app/release?limit=2` | 返回 v1.15 + v1.14，`history` 长度 2 |
| `GET /api/app/update-check?versionCode=12` | `hasUpdate: true`，`signatureChanged: false` |
| `GET /api/app/update-check?versionCode=8` | `signatureChanged: true` |
| `GET /api/app/release/v1.10` | 返回该版本详情；`v9.9` 返回 404 |
| `/api/health` | `serverVersion 1.2`、`uptimeSeconds`、`watchVersion` 正常 |
| `GET /api/download/list` | 返回 `files: []` 与 `preferred`，`latestAppVersion 1.15` |
| 长轮询唤醒 | 保存配置后 **2.07 秒**返回 `changed:true`（请求已挂起） |
| 长轮询空转 | 无变化时挂起 **25.04 秒**返回 `changed:false` |
| 家长后台「版本与更新」 | 渲染出最新版徽章 + 3 条版本记录，无报错 |

## 六、还没做的一件事

**客户端尚未接 `/api/app/update-check`**。服务端接口已就绪，客户端要做的是：

- 在家长面板「关于」处加一个「检查更新」按钮（不要自动弹窗，儿童界面不该出现升级弹窗）；
- 拿到 `hasUpdate=true` 且 `signatureChanged=false` 时展示版本说明与下载入口；
- `signatureChanged=true` 时只显示「需卸载后安装」的说明，不提供直接跳转。

这样做的好处：不需要接入任何应用市场 SDK，也不需要企业资质。
