# 网页小游戏手机端适配说明

> 适用：游戏乐园内置的 13 款网页小游戏（`Resources/Raw/Playland/`）
> 版本：v1.14 起生效　更新日期：2026-11-04

---

## 一、问题现象（真机截图确认）

| 游戏 | 现象 |
|---|---|
| 欢乐五子棋 | 棋盘只露出下半截，被下方「模式选择」面板盖住；顶部标题与按钮挤成一竖排 |
| 中国象棋 | 棋盘右侧一排棋子被裁掉；标题被右上角按钮压住 |
| 森林斗兽棋 | 顶部按钮文字竖排换行、互相重叠；底部战况面板永远看不到 |
| 点字成诗 | 标题竖排占满左侧，按钮行超出右边界，最右边的「拼音开关」看不见 |
| 冰雪打企鹅 | 画面被夹在中间，底部卡片被截断 |
| 算术小飞行员 | 顶部状态条（距离 / 得分）超出右边界 |

## 二、根因（两条，互相叠加）

**1. 页面是按桌面宽度写的**

13 个页面原始设计宽度 ≥820px，且大量使用：
- `html, body { height: 100%; overflow: hidden }` —— 内容超出一屏就直接被裁掉，没有滚动；
- `display:flex` 且 `flex-wrap:nowrap` 的按钮行、状态条 —— 窄屏不会换行，只会溢出；
- `canvas` 用内联像素宽度（如五子棋 600×600）—— 内联样式优先级高于普通 CSS，不写 `!important` 压不住；
- 竖排标题（`writing-mode: vertical-rl`）—— 桌面是装饰，手机上占掉半屏。

**2. WebView 自身的两个默认行为**

- **桌面视口**：Android WebView 默认可能按 980px 布局再缩放，页面按桌面排版，结果就是「棋盘只露一半、按钮叠在一起」。必须 `UseWideViewPort = true` + `LoadWithOverviewMode = false`。
- **跟随系统字体**：部分国产 ROM 把系统字体调大后，WebView 的 `textZoom` 会跟着变，网页文字被放大，固定像素布局被撑破。固定 `TextZoom = 100` 解决。

## 三、做了什么

### 1. 一份共享样式表

`pages/assets/mobile.css`，由 13 个页面 + 大厅页在 `<head>` 里引用。**只在 `max-width:820px` 生效**，桌面/PAD 横屏表现与原来完全一致。

包含六组规则：

| 组 | 作用 |
|---|---|
| 1 | 图片/视频/画布不超宽（`canvas{max-width:100%!important}`） |
| 2 | 顶部导航允许换行，压缩按钮字号与内边距 |
| 3 | 侧栏/面板改为满宽，不再固定 300+ 像素 |
| 4 | ≤380px 再压一档 |
| 5 | 按钮组自身允许换行；竖排标题改横排 |
| 6 | 状态条（血量/速度/距离/得分）允许换行 |

另有一段「解除高度锁死」：`html` 与 `body` 都改为自然高度 + 纵向滚动。**必须同时改 `html`** —— 只改 `body` 的话，裁剪会落到 `html` 上，内容依旧看不到。

### 2. 画布类游戏不动布局

俄罗斯方块式、贪吃蛇、雷霆战机这类游戏的画布靠 JS 按容器算尺寸，CSS 只加 `max-width` 上限，不改高度语义，避免画布塌成 0。

### 3. WebView 参数（`Pages/PlaylandPage.xaml.cs`）

```csharp
s.UseWideViewPort = true;        // 按 device-width 布局
s.LoadWithOverviewMode = false;  // 不要缩放整个页面
s.SetSupportZoom(false);
s.BuiltInZoomControls = false;
s.DisplayZoomControls = false;
s.TextZoom = 100;                // 忽略系统字体缩放
awv.OverScrollMode = Never;      // 去掉边界辉光
```

### 4. 资源版本号

`Helpers/PlaylandAssets.cs` 的 `Version` 由 `1` 改为 `2`，并把 `pages/assets/mobile.css` 加进清单。安装新包后会重新释放网页资源，否则应用会继续用旧缓存，改了半天看不到效果。

## 四、怎么验证

**最省事的办法**：改完直接在本机用无头 Chrome 按手机视口截图，不用等真机。

```bash
# 390x844 手机视口下渲染任一游戏
chrome --headless=new --window-size=400,880 \
  --screenshot=out.png --virtual-time-budget=3500 \
  "file:///<工程路径>/Resources/Raw/Playland/pages/gomoku.html"
```

注意：无头 Chrome 有最小窗口宽度，直接截 390 会失真。更准的做法是把页面放进一个 `width:390px` 的 iframe 再截图（`_shots/frame.html` 就是这么做的）。

**量化检查**：读出每个页面里「被 overflow:hidden 裁掉的内容量」和「超出视口的元素」，比肉眼看更快定位：

```js
el.scrollWidth - el.clientWidth   // >0 且 overflow-x:hidden → 横向被裁
el.scrollHeight - el.clientHeight // >0 且 overflow-y:hidden → 纵向被裁
```

本次修复后，13 个页面在 360 / 390 / 480 三种宽度下均无横向溢出，纵向内容可滚动。

## 五、以后新增网页游戏时的检查清单

- [ ] `<head>` 里有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
- [ ] 引用 `assets/mobile.css`
- [ ] 不用 `html,body{height:100vh;overflow:hidden}`；必要时只对某个内部容器用
- [ ] 按钮行、状态条不要写 `flex-wrap:nowrap`
- [ ] 画布用 `width:100%;height:auto` 或 `aspect-ratio`，不要写死像素
- [ ] 把文件加进 `PlaylandAssets.Files`，并把 `Version` +1
- [ ] 按 360 宽度截图确认一次
