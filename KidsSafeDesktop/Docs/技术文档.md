## 3. 关键实现

### 3.1 天气 + 自动定位（逐小时 + 预警）
- `IWeatherService.GetForecastAsync(city)`（主页使用）与 `GetCurrentAsync(city)`（兼容）：
  1. 定位：`city=="auto"`/空 → `GET https://ipwho.is/`（IP 定位，返回城市/经纬度）；否则 `GET https://geocoding-api.open-meteo.com/v1/search?name={city}`（中文城市名解析）。
  2. 天气：`GET https://api.open-meteo.com/v1/forecast?...&current=...&hourly=temperature_2m,weather_code,precipitation_probability&forecast_days=1&timezone=auto`。
  3. WMO `weather_code` 映射为中文描述 + emoji（`WeatherService.MapDescription` / `MapEmoji`，已提升为 public static 复用）。
- **逐小时**：解析 `hourly` 数组，从当前小时起取未来最多 12 小时，封装为 `WeatherHour`（时间/温度/emoji/降水概率）。
- **预警推导**：Open-Meteo 免费接口不含官方预警，故 `DeriveAlerts(...)` 依据逐小时数据本地推导（高温≥35°、低温≤0°、降水概率≥60%、风速≥30km/h、雾、雷暴），分「预警/注意」两档，封装为 `WeatherAlert`。无官方预警源也能给出提醒。
- 主页天气卡片：`WeatherHours`（横滑逐小时）+ `WeatherAlerts`（按级别着色的提醒条），点卡片可手动刷新。
- 全程 8s 超时 + try/catch，失败返回 `null`，主页隐藏天气卡片（优雅降级）。
- `city` 来自 `ChildSettings.WeatherCity`（可被服务器统一管理）。

### 3.2 家长端服务器协议
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/login` body `{pin}` | 密码正确返回 `{ok,token}`；否则 401 |
| GET  | `/api/settings?token=` | 返回 `ManagedProfile`（需有效令牌） |
| PUT/POST | `/api/settings?token=` body `ManagedProfile` | 保存（覆盖） |
| GET  | `/api/watch?token=&since=` | 实时下发通道：挂起最多 25 秒，配置有变立即返回 `{version,changed:true}`；无变化返回 `false`；客户端断开返回 **204** |
| GET  | `/api/health` | 健康检查 |

- 令牌为固定共享串 `kids-admin-token`（登录即下发）。**仅适合受信任局域网/本机**；公网需 HTTPS + 账号体系。
- 服务端字段与客户端 `RemoteProfile` 一致，可直接 JSON 映射。
- **`/api/watch` 取消不抛异常**：浏览器关页面/切网时请求会被取消，`WatchSignal.WaitAsync` 返回 `null` 而不是抛 `OperationCanceledException`。这样才能让「异常设置 → 引发时中断」保持开启而不被长轮询正常取消刷屏，也避免调试器停在异常展开的帧上导致局部变量窗口只显示「在异常调用堆栈中不可用」。

### 3.3 客户端同步（`ServerSyncService`）
- `LoginAsync(pin)` → 保存 `ChildSettings.ServerToken`。
- `PullAsync()` → `Apply()` 将远端配置合并到本地：时长、游戏开关、主题（`ThemeService.SetTheme`）、昵称、天气城市、喜马拉雅默认分类、允许应用白名单（重建 `AppItem` 列表）、**在线内容总开关**（见 3.32）。
- 家长后台「立即同步」成功后调用 `RebindAsync()` 刷新本地 UI。

### 3.4 媒体中心（听一听 · 离线音频）
- **媒体中心**（`MediaHubPage`）数据源为随包发布的内容库 `KidsAudioData`，`MediaHubViewModel` 直接暴露
  `ObservableCollection<KidsAudioGroup>`（不再有第三方「提供方」概念）。
- 六个分组：儿歌音乐盒、安睡摇篮、睡前故事、国学启蒙、英语启蒙、科普知识；每组的条目 `KidsAudioItem`
  通过 `Kind`（`Music` / `Ambient` / `Speech`）区分介质。
- 分类点击 → `AudioPlayerPage(group, item)`，**统一播放**，详见 **3.25**。
- 不再需要任何网络权限来收听（原先依赖 `INTERNET` 加载第三方网页，现已完全离线）。

### 3.5 主题系统
- `AppTheme` + `ThemeService`（单例）：三套主题含背景图、顶栏渐变、磁贴渐变、强调色。
- 页面绑定 `ThemeService.Instance.CurrentTheme.BackgroundFile` 显示背景；`ChildSettings.ThemeId` 持久化。

### 3.6 小游戏要点
- **连连看**：经典「≤2 拐弯」BFS 连通判定（可绕棋盘外圈），消除后该格在寻路网格中置空；无解自动洗牌。
- **走迷宫**：回溯算法（recursive backtracker）生成；点相邻通道格移动熊猫至终点判胜；难度决定迷宫尺寸。

### 3.7 账号体系 + 离线模式
- `IAccountService` / `AccountService`：本地优先、离线可用。
  - `EnsureAccountAsync()`：首次运行在 `ChildSettings` 生成 `AccountId` + `AvatarEmoji`，创建**离线账号**；`App.OnStart` 调用。
  - `Current.Mode` 由 `ChildSettings` 的 `ServerEnabled + ServerUrl + ServerToken` 推导：`Online` 需三者齐备，否则 `Offline`。
  - `ConnectServerAsync(url, pin)`：写入服务器地址并启用，调用 `ServerSyncService.LoginAsync` 登录，成功即 `PullAsync` 同步；失败回滚为离线并抛异常。
  - `DisconnectAsync()`：清除启用状态与令牌，切回离线。
- `AccountPage`：修改昵称/头像、显示模式、连接/断开服务器；主页右上角徽章（`AccountBadge`）实时显示「🟢 离线模式 / ☁️ 已联网」。

### 3.20 TTS 实时语音助手（统一封装 + 接入清单）
- `Helpers/Tts.cs`：静态 `Tts.SpeakAsync(text, localePrefix)` 统一封装 `Microsoft.Maui.Media.TextToSpeech`。`localePrefix` 支持 `"en"`（英文）/`"zh"`（中文）：按前缀/包含匹配选择已安装语言包。**健壮性设计（重要）**：
  1. `GetLocalesAsync()`（查询语言列表）在独立的 try/catch 中执行，其异常**不会阻断**真正的朗读——早期版本把二者放在同一个 try 里，一旦查询语言列表抛异常（设备无 TTS 引擎/无语音数据时常见），`SpeakAsync` 根本不会被调用，导致**全局无声且无任何报错**；
  2. 未匹配到语言包或朗读失败时，自动**回退到系统默认语音**（不带 `Locale` 再试一次），最大化出声概率；
  3. 异常不再静默吞掉：记录到 `Tts.LastError` 并输出 `Debug.WriteLine` / `Console.WriteLine`（DEBUG），便于定位“设备缺少语音包”等环境问题。
- **可用性探测**：`Tts.ProbeAsync()` 返回 `(Available, Detail)`，在 `HomePage.OnAppearing` 中启动时探测一次（`_ttsProbed` 去重）；若不可用则弹窗提示并给出安装指引（Windows：设置 → 时间和语言 → 语音，下载语音包；Android：设置 → 系统 → 文字转语音(TTS)输出，安装 Google TTS 引擎与语音数据）。

- **页面**（`Pages/PlaylandPage.xaml(.cs)`）：
  - 顶部工具栏 `← 返回 / 🏠 大厅 / 🔄 刷新`，解决网页游戏自身返回入口不易发现的问题；
  - `Navigating` 事件只放行 `file://`，外链交给系统浏览器，避免在应用内打开陌生网页；
  - Android 端在 `HandlerChanged` 后配置 `JavaScriptEnabled / DomStorageEnabled / AllowFileAccessFromFileURLs / MediaPlaybackRequiresUserGesture=false`，保证 Canvas 游戏与 Web Audio 音效可用；
  - 资源释放期间显示加载遮罩。
- **入口**：首页「🕹️ 游戏乐园」磁贴 → `OnPlaylandTapped` → `PushAsync(new PlaylandPage())`。

### 3.24 任务栏恢复与异常退出兜底（Windows）

**背景**：儿童模式（kiosk）进入时对 `Shell_TrayWnd` 调用 `ShowWindow(SW_HIDE)` 隐藏 Windows 任务栏。
这属于**修改 explorer.exe 的全局窗口状态**：进程一旦崩溃、被强杀或遭遇系统关机，这一步**不会自动回滚**，
任务栏会一直消失，用户只能手动重启资源管理器。原实现仅在 `ExitAppAsync()`（家长后台正常退出）中恢复，
其余退出路径全部遗漏。

**修复：四层兜底**

| 层级 | 机制 | 覆盖场景 |
|------|------|----------|
| 1 | 窗口激活跟踪：`Activated` → 隐藏，`Deactivated` / `Closed` → 恢复 | **把任务栏被隐藏的时间窗口压到最小**：只有本应用真正在前台时才隐藏；启动外部应用、Ctrl+Alt+Del、最小化都会立刻还原。此时即使进程被硬杀，任务栏大概率已是显示状态 |
| 2 | `AppDomain.CurrentDomain.ProcessExit` | 正常退出、窗口关闭、`Exit()` |
| 3 | `AppDomain.UnhandledException` + `TaskScheduler.UnobservedTaskException` + `Microsoft.UI.Xaml.Application.UnhandledException` | 崩溃（UI 线程 / 后台线程 / 未观察的 Task 异常） |
| 4 | **启动自检**（标记文件） | 硬杀（`taskkill /f`）、`FailFast`、系统断电——钩子来不及执行的最后防线 |

**标记文件机制**：隐藏任务栏前先写标记 `.taskbar_hidden_by_kids`（落盘成功再隐藏）；
正常恢复后删除标记。下次启动时 `RecoverTaskbarIfNeeded()` 若发现标记残留，
即可断定上次是异常退出，立即恢复任务栏——**用户无需手动重启资源管理器**。

**关键实现点**
- `_taskbarHidden` 标志：只恢复由本进程隐藏的状态，避免误改他人状态
- `_exiting` 标志：正常退出后置位，防止后续的 `Activated` 事件把任务栏再次隐藏
- `_trackedWindow`：避免重复订阅激活事件
- 全部逻辑 try/catch，兜底机制本身绝不能影响启动
- 注册时机：WinUI 入口 `Platforms/Windows/App.xaml.cs` 构造函数中（最早执行的用户代码）

**实测验证**（通过 P/Invoke 查询 `Shell_TrayWnd` 可见性）

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 应用运行中 | `False`（kiosk 隐藏，正常） | `False` ✓ |
| 强制杀进程后 | `False`（卡死，任务栏消失） | `False`（硬杀无法拦截） |
| 重新打开应用 | `False`（**须手动重启资源管理器**） | **`True` 启动自检自动恢复** ✓ |
| 关闭窗口正常退出 | `False`（**异常**） | **`True`** ✓ |

**用户自救入口**：帮助页顶部新增「🖥️ 恢复任务栏」按钮，任何时候可一键找回；
帮助条目新增「电脑底部的任务栏不见了？」。

### 3.25 听一听：离线音频播放中心（改造）

**改造背景（缺陷）**：原先媒体中心把第三方儿童站塞进 WebView，`MediaHubViewModel` 的分类 URL 指向的是
**官网首页**（贝瓦 `https://www.beva.com/`、宝宝巴士 `https://www.babybus.com/`）与
**搜索页**（喜马拉雅 `https://www.ximalaya.com/search/?q=儿歌`），同一提供方下所有分类共用同一条 URL。
结果是：点任意分类都跳到官网/搜索页而非播放页，需要二次操作才能听；更严重的是实测喜马拉雅搜索页
热门推荐混有成人向言情内容，第三方站内还有登录墙与 VIP 弹窗——与「儿童安全桌面」的定位冲突。

**方案**：彻底移除第三方网页内嵌，改为**随包发布的离线内容 + 原生播放器**。

- 依赖：**无新增 NuGet**。播放通过自建的 `IAudioPlayerService` 调用各平台原生播放器。
- 内容库 `Models/KidsAudioData.cs`：6 个分组，三类内容
  - `Music` 儿歌音乐盒（8 首）：`Resources/Raw/Audio/song_*.wav`
  - `Ambient` 安睡摇篮（3 段）：雨声/海浪/白噪音，`Loop=true`
  - `Speech` 朗读类：睡前故事 6 篇、国学启蒙 8 首唐诗/三字经、英语启蒙 6 组、科普知识 6 问，
    由 `Helpers/Tts` 逐句朗读
- 音频生成：`Docs/tools/generate_kids_audio.py`（可重复执行）。
  儿歌曲调**全部取自公有领域**（Twinkle、Frère Jacques、Happy Birthday、Jingle Bells 等），
  用 numpy 以音乐盒音色（基频+2/3/5.1 次谐波、指数衰减包络）合成 16kHz/16bit 单声道 WAV，
  再叠一层低八度正弦衬底增加厚度；环境音用 Voss-McCartney 粉红噪声 + 一阶低通 + 缓慢 LFO 包络。
  全部合计 9.75 MB。
- **播放内核 `Services/IAudioPlayerService`**（实现见 3.26）：不引用任何第三方 XAML 宿主控件，
  直接由各平台原生播放器提供播放能力。
- 资源释放 `Helpers/KidsAudioAssets.cs`：播放器只能读真实文件路径、读不了应用包内的资源流，
  故沿用 `PlaylandAssets` 的模式，首次播放时把 `Audio/*.wav` 释放到 `FileSystem.AppDataDirectory/audio`，
  并用 `.assetversion` 标记做幂等（含"抽查任一文件缺失则重释放"）。
- 播放页 `Pages/AudioPlayerPage.xaml(.cs)`：单页同时处理两种介质。
  - 音乐/环境音：`await IAudioPlayerService.SetSourceAsync(path, loop)` → `Play()`；
    循环由底层保证；用 `Dispatcher.CreateTimer()`（400ms）轮询 `PositionSeconds/DurationSeconds` 驱动进度条，
    `Slider` 的 `DragStarted/DragCompleted` 控制拖动期间不轮询并 `SeekTo`；`Ended` 事件自动播放下一首
    （环境音因已循环而跳过）。
  - 朗读类：`SpeechLine` 承载一行文本，并用 `Background/TextColor/Attributes` 计算属性实现高亮；
    `StartSpeechAsync(start)` 顺序 `await Tts.SpeakAsync(line, locale)`，
    用 `CancellationTokenSource` 实现暂停/切句；进入时 `Tts.ProbeAsync()`，无语音包则显示指引按钮跳帮助页。
  - `OnDisappearing` 统一 `StopAll()`，避免离开页面后仍在播放。

### 3.26 原生音频播放服务（放弃 CommunityToolkit.Maui.MediaElement）

首版实现使用了 `CommunityToolkit.Maui.MediaElement` 4.1.0，结果在 Windows 端**进入播放页即整个进程崩溃**
（`System.InvalidOperationException` thrown in `XamlLParse.dll`，退出码 `0xC000027B`）。

排查过程（值得记取的定位手段）：临时在 `HomePage.OnAppearing` 里加一段自动导航到播放页的代码，
并在播放流程各步骤写文件日志，得到逐字轨迹：

```
ctor OK → OnAppearing enter → PrepareAsync enter → StopAll done
→ assets extracted ok → path=...song_twinkle.wav exists=True
→ source set OK → Play() invoked → PlayAsync: after → push OK → (进程终止)
```

可见**每一步托管代码都成功**，崩溃发生在原生播放管线启动后；进一步把 `Play()` 注释掉，
**仅设置 Source 仍会崩溃**，从而断定是宿主控件本身（该包仅面向 net8.0，本项目为 net10.0）不可用，
而非播放时序问题。由于是 fail-fast 退出而非托管异常，异常回调不会触发，只能靠文件日志定位。

结论：**移除该依赖**，改为自建跨平台播放服务。

| 平台 | 实现 | 关键 API |
|------|------|----------|
| Windows | `Platforms/Windows/WindowsAudioPlayerService.cs` | `StorageFile.GetFileFromPathAsync` → `MediaSource.CreateFromStorageFile` → `Windows.Media.Playback.MediaPlayer`（`AutoPlay=false`，`IsLoopingEnabled` 控制循环） |
| Android | `Platforms/Android/AndroidAudioPlayerService.cs` | `Android.Media.MediaPlayer`（`Looping` 控制循环，`Completion` 仅在非循环时回调） |
| 其他 | `Services/StubServices.cs` 中的 `StubAudioPlayerService` | 空实现，保证模板目标可编译 |

注册方式同其它平台服务（`MauiProgram` 中按 `#if ANDROID / #elif WINDOWS / #elif IOS||MACCATALYST` 分支注册）。
> 注意：`StubAudioPlayerService` 与其它桩实现一样位于 `#if IOS || MACCATALYST` 条件编译块内，
> 注册语句必须写在同一个分支里，否则 Windows/Android 会因找不到类型而编译失败。

**踩坑**：
1. `Windows.Media.Playback.MediaPlaybackItem.OpenAsync(...)` 在 WinRT 投影中不存在（CS1929）。
   改为直接赋 `MediaPlayer.Source`，再轮询 `PlaybackSession.NaturalDuration` 最多 1 秒取时长。
2. `Dispatcher.CreateTimer(...)` 在本版本只接受**无参**调用，需先 `CreateTimer()` 再设 `Interval`。
3. 项目根目录有 `KidsSafeDesktop.slnx`（内含 `KidsSafeServer` 子项目），`dotnet build -f <tfm>` 会连带构建它
   并报 `NETSDK1005`；构建时应显式指明 `dotnet build KidsSafeDesktop.csproj -f <tfm> -c Debug`。

**实测验证**：自动进入播放页后进程存活，探针输出
`dur=27.69 pos=0.83/1.84/2.86/3.86/4.88 playing=True` —— 时长与生成的 `song_twinkle.wav` 完全一致，
进度线性推进，确认 Windows 端播放链路已通。

**清理**：删除 `Pages/MediaPlayerPage.xaml(.cs)`（第三方 WebView 播放器）与 `Models/MediaProvider.cs`。
`IXimalayaService` 及各平台实现暂保留但已无任何调用点。

### 3.27 我的日记（孩子自设密码 + 本地存储）

**定位**：与「关爱中心 → 心情日记」并存、互不联动。心情日记是每天一条心情、不设防、给家长看的；
我的日记是自由书写、设 4 位密码、只给孩子自己的。两者共用 `CareCatalog.Moods` 的心情清单，但数据完全分开。

**存储**（`Services/DiaryStore.cs`）
- 路径 `AppDataDirectory/diary_v1.json`，`System.Text.Json` 序列化 `DiaryBook`。
- 写入方式：先写 `diary_v1.tmp`，再 `File.Move(tmp, target, overwrite: true)`。断电或强杀进程时，
  要么是旧文件、要么是新文件，不会出现半截 JSON。
- 上限：2000 篇、单篇正文 20000 字。超限时**丢弃最旧一篇**而不是拒绝写入——孩子正在写的时候弹「存不下了」是最差体验。
- 文件损坏（`JsonException`）时按空本处理，且**不覆盖原文件**（重命名为 `.broken-<ticks>` 保留），内容还有救。

**密码**（`Services/DiaryLock.cs`）
- 只存 `PBKDF2-HMAC-SHA256(pin, salt, 100000, 32)` 的 Base64 + 16 字节随机盐 + 迭代次数，
  没有任何明文，也没有可逆推的校验位。
- 比较用 `CryptographicOperations.FixedTimeEquals`，避免因比较耗时差异泄露前缀。
- 冷却：累计 5 次 → 60 s，8 次 → 180 s，12 次起 → 300 s。`LockedUntilTicks` 落盘，
  杀进程重开也绕不过；冷却期内**正确密码同样拒绝**（返回 `Locked`）。
- **任何路径都不删除日记**。忘记密码只能由家长 PIN 重置（`Reset` / `ResetAndClear`）。
- 隐私边界写在设密码页上：重置后内容保留但家长可读。**日记文件本身不加密**——
  密钥若写在代码里，加密只是心理安慰；这条已同步进 `ComplianceContent.cs` 与应用内隐私政策第 06 节。

**页面**（`Pages/DiaryPage.xaml(.cs)`）
- 单页四状态：设密码 / 锁屏 / 日记本 / 编辑器，用 `IsVisible` 切换，不新建页面栈。
- 键盘自绘（`Grid` 3×4），不用系统输入框：系统数字键盘在小屏上会顶起布局，且部分 ROM 会记录输入。
- 离开页面（`OnDisappearing`）即重新上锁；`OnSleep` 时静默保存草稿。
- 字数统计走 `Rune` 枚举 + `UnicodeCategory` 白名单，emoji 不算字。**不要用 `string.Length`**：
  一个 😄 是代理对，会被算成 2 个字，孩子写满表情会看到离谱的数字。
- **不发星星**：星星会进星星榜与家长面板，等于向家长泄露「今天写日记了」。

### 3.28 俄罗斯方块 / 两款网页游戏 / 成长指南（v1.19）

**① 俄罗斯方块（原生，第 21 款小游戏）**

- 文件：`ViewModels/TetrisGameViewModel.cs`（规则）、`Pages/TetrisDrawable.cs`（绘制）、`Pages/TetrisGamePage.xaml(.cs)`（页面）。
- 10×20 棋盘，用 `int[Rows, Cols]` 存落定方块（0 空、1..7 为方块类型），当前方块用 4×4 掩码表示：**旋转就是纯矩阵操作**，不必为每种形状维护 4 个朝向。
- 三处儿童向取舍：旋转撞墙时自动左右平移（wall kick），乱按不会卡死；消行给固定分不看连击，避免为了刷分堆高危局面；结束条件是「新方块放不下」，比计时直观。
- 随机用 7-bag（一轮 7 种各一次），避免连续掉同一种方块。
- 幽灵落点（`GhostY`）用半透明描边画出，孩子知道「直落会停在哪」。
- 绘制颜色取 `PieceType`，**不要靠形状反推类型**：T/J/L 旋转后的「格子数 + 包围盒」完全相同，反推会串色。

**② 两款网页游戏接入「游戏乐园」**

- `Resources/Raw/Playland/pages/car_rush.html`（小汽车大冒险，来自 `x.html`）与 `pages/light_puzzle.html`（光线宝石，来自 light-puzzle 项目）。
- 两份都是单文件 Canvas 游戏，原实现带触摸/鼠标/音效，**直接原样打包比移植成 C# 更省事、也更还原**。
- 接入只需三步：放进 `pages/`、登记 `PlaylandAssets.Files`、把 `Version` 常量 +1 触发重新释放；大厅 `index.html` 加两张卡片（`.card-car` / `.card-light` 配色类）。
- 改了 `car_rush.html` 的一处 bug：触摸左右半屏判断原来用 `clientX < W/2`（`W` 是画布内部像素宽），画布被居中或缩放时会偏；改成 `clientX - rect.left < rect.width/2`。
- `light_puzzle.html` 补引 `pages/assets/mobile.css`，与其余 13 款共用窄屏适配（`canvas{max-width:100%!important}` 防止固定 720×540 画布横向溢出）。`car_rush.html` 不加：它是按窗口尺寸自适应的全屏画布，加了反而会把 `html` 高度放开、出现滚动条。

**③ 0-15 岁成长指南（家长向，WebView）**

### 3.30 SQLite 题库（口算五～九年级 + 英语一～九年级）

**为什么换成 SQL**

原来口算靠 `OralGenerator` 现场算、英语词库是 `EnglishData` 里的 108 条静态数组。前者没法表达「小数/分数/有理数/方程/根式/函数」，后者加到初中就是上千条，写在代码里既臃肿又难维护。所以把**静态内容**搬进 SQLite，**动态生成**留在代码里：

| 内容 | 存储 | 原因 |
|---|---|---|
| 口算 1-4 年级 | `OralGenerator` 程序生成 | 纯四则，随机不重复，无余数问题 |
| 口算 5-9 年级 | `math_problem` 表（368 题） | 题型多、答案固定，适合题库 |
| 英语词库 1-9 年级 | `english_word` 表（411 词） | 纯静态数据，本来就不该硬编码 |

**文件与流程**

- 包内资源：`Resources/Raw/questbank/seed_math.sql`、`seed_english.sql`（`MauiAsset`，逻辑名 `questbank/xxx.sql`，随 APK 走 `assets/`）。
- 运行时：`Services/QuestionBank.cs` 首次调用时在 `AppDataDirectory/questbank.db` 建表 → 执行两份种子脚本 → 写入 `meta.seed_version` 与 `meta.seed_fingerprint`。
- **重灌判断看脚本指纹，不看手写版本号**：指纹是两份 `.sql` 内容和文件名的 SHA-256。早期只比 `seed_version`，改题时忘了 +1，老库就永远读旧题（开发机上真的踩到了：旧「方差」题答案 2.6667 留在库里，孩子根本输不进去）。改成指纹后，脚本一改下次启动自动重灌，不再依赖人记性；`seed_version` 保留只作诊断。
- **读不全就不灌**：两份脚本任一为空/缺失直接抛异常，且不写指纹 —— 宁可这次降级，也不要把半套数据标记成"已是最新"，下次启动还能重试。
- **初始化放在 `Task.Run` 里**：页面构造函数是同步调用，直接在 UI 线程上等 `OpenAppPackageFileAsync` 在 WinUI 上可能死锁；包一层线程池再 `GetAwaiter().GetResult()` 就安全了。
- 失败兜底：任何异常都置 `IsAvailable=false`，`PickMath` 返回空表 → 口算回落 `OralGenerator`，英语 `BuildQuiz` 返回空 → 页面提示「词库还在准备」，不崩、不白屏。

**表结构**

```sql
CREATE TABLE math_problem(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  grade INTEGER NOT NULL,        -- 5..9
  topic TEXT NOT NULL,           -- add/sub/mul/div/mix，对应题型芯片
  category TEXT NOT NULL,        -- 显示用：有理数加法 / 一元一次方程 / 圆的面积
  expression TEXT NOT NULL,      -- 题干，如 "(-3) + 7 = ?"
  answer REAL NOT NULL           -- 答案，允许负数与两位小数
);
CREATE TABLE english_word(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  grade INTEGER NOT NULL,        -- 1..9
  category TEXT NOT NULL, word TEXT NOT NULL, meaning TEXT NOT NULL,
  phonetic TEXT NOT NULL DEFAULT '', emoji TEXT NOT NULL DEFAULT ''
);
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

**取题**：`SELECT ... WHERE grade=$g AND topic=$t ORDER BY RANDOM() LIMIT $n`；该题型在本题库里没有题时自动去掉 topic 条件再查一次（初中的「加法」题本来就少），保证点了芯片一定有题。

**改题目 / 加题目**：只改 `seed_*.sql`，重新打包即可 —— 重灌判断看的是脚本指纹（两份 `.sql` 的 SHA-256，存在 `meta.seed_fingerprint`），内容一变老用户升级后第一次进页面就会自动重灌，不需要清数据，也不依赖"记得把版本号 +1"。

**答案约定**：全部是整数或最多两位小数，且**不出现分数答案**（孩子只能用数字键盘输入）。所以分数题都设计成结果为整数或小数，例如 `1/2 + 1/2 = ?`、`3/4 × 8 = ?`。负数用输入框右侧「±」键切换，DecimalPoint 由 `Keyboard="Numeric"` 提供。

**朗读**：`OralPracticeViewModel.BuildSpoken` 改成按字符解析，支持小数（一点二）、负数（负三 / 括号负三括号）、平方（的平方）、立方、根号、三次根号、绝对值、括号、°、比号，避免初中题目被读成「减 三 括号」。

### 3.31 电子课本（语文 2 个版本 · 数学 9 个版本）

**为什么不做"客户端下载 PDF"**

语文 24 本 438 MB、数学 106 本 7.6 GB，单本十几兆、100–150 页。直接把 PDF 塞进安装包不现实，让客户端下原件再找系统阅读器打开也与儿童桌面的"全屏、不乱跳"冲突（安卓 WebView 本身不渲染 PDF）。

所以走**服务端预渲染页图**：每页导成 120 DPI 的 jpg（约 115 KB/页），客户端只按页取图，翻到哪页下载哪页，并缓存到本地。好处是翻页快、可离线回看、不跳出应用；代价是服务端多占约 1.8 GB 图片。

**三层结构：科目 → 版本 → 年级**

同一年级不同教材版本的内容差别很大（人教、北师大、苏教、青岛…），所以清单里多了一层"科目"：

```
books.json
  subjects: [ { id:"chinese", name:"语文", icon:"📖" },
              { id:"math",    name:"数学", icon:"🔢" } ]
  editions: [ { id:"rj", name:"人教版（六三制）", short:"人教", subject:"chinese", maxGrade:6 },
              { id:"math-bsd", name:"北师大版", short:"北师大", subject:"math", maxGrade:6 }, … ]
  books:    [ { id:"math-bsd-2b", subject:"math", edition:"math-bsd", grade:2, term:2, year:"2026春版", legacy:false }, … ]
```

书号规则：`{科目}-{版本}-{年级}{a上册|b下册}`，如 `math-bsd-2b` = 北师大版二年级下册；`-old` 后缀是同册的旧版存档（同一册既有带年份的现行版、又有不带年份的旧档时才会打）。语文沿用早期书号 `rj-1a` / `rj54-5b`，不重命名以免动 3000 多张页图。

**目录结构（服务端 `wwwroot/books/`）**

```
books/
  books.json                      # 清单：科目 / 版本 / 课本
  pages/<书号>/page-0001.jpg …    # 页图，0001 同时也是封面
  pdf/<书号>.pdf                  # 原件，供家长下载打印（支持 Range，可断点/跳页）
```

原件与源文件同盘时用**硬链接**，不额外占空间；跨盘才退回复制。

**接口**

| 接口 | 说明 |
|---|---|
| `GET /api/books` | 返回 `subjects`（科目 + 册数 + 版本 id 列表）与 `editions`（扁平，每个版本带 `subject`/`short`/`books`） |
| `GET /api/books/{id}` | 单本详情 |
| `GET /books/pages/{id}/page-0001.jpg` | 静态页图 |
| `GET /books.html` | 电脑浏览器翻页版，支持 `?subject=math`、`?read=math-rj-5a&p=36` 深链 |

`editions` 保持扁平是为了兼容：老客户端只认 `editions`，不认识 `subjects`，照样能把 11 个版本平铺出来。一本页图都没有的版本和册数为 0 的科目都不会出现在响应里，避免客户端点开是空的。

**页数以磁盘为准**：`TextbookCatalog` 不信清单里写的页数，而是数 `pages/{id}/page-*.jpg` 的实际个数；清单按文件修改时间缓存，换书、加书不用重启服务。

**客户端的缓存三层**：目录内存缓存 10 分钟 → 目录另存一份 `AppData/textbooks/shelf.json`（断网也能看到书单）→ 页图按 `textbooks/{书号}/page-0001.jpg` 落盘（看过的不再联网）。相邻页会在翻页时后台预热，快速连点用自增请求号防竞态。

**批量渲染脚本**：`Scripts/BookRender/render_subject.py`

```bash
python Scripts/BookRender/render_subject.py --subject math --name 数学 --icon 🔢 \
    --src "D:/小学数学" --out "D:/WorkBuddy/KidsSafeServer/wwwroot/books"
```

- 一个科目目录下多个版本文件夹一次跑完，版本表在脚本顶部 `EDITIONS` 里维护；
- 断点续跑：已有页图的书写进日志并跳过，补渲染失败的那几本用 `--only <书号>`；
- 合并清单是"按 id 覆盖 + 保留未参与本次渲染的"，所以补跑单个版本**不会**把本科目其它书从清单里冲掉；
- 日志写到 `Scripts/BookRender/logs/`，**不能**放 `wwwroot`：会被静态资源打包任务当成资源去算指纹，日志正在写的时候直接把 `dotnet build` 卡死。

**渲染踩到的坑**：`workbuddy-pdf` 的 CLI 读不了非 ASCII 路径（先把 PDF 拷成 `math-rj-1a.pdf` 再渲染），也解析不了个别 2026 春版（所有格式都静默返回 127），后者改用 Windows 自带的 `Windows.Data.Pdf` 渲成 PNG 再转 jpg 补齐。

### 3.32 在线内容总开关（家长端 ⇄ 服务端）

**问题**：`ChildSettings.OnlineContentEnabled` 从引入起就没有任何入口能改——服务端 `ManagedProfile` 里没这个字段，客户端家长页也没有开关，它恒为 `false`。结果是宝宝听 / 宝宝看 / 亲子阅 / 故事屋 / 电子课本的在线分支永远走不到，只剩离线内置内容。

**现在两端都能改，且以服务器为准**：

- 服务端后台（`wwwroot/index.html`）新增「📚 在线内容」卡片 → `ManagedProfile.OnlineContentEnabled`；
- 客户端家长主页（`ParentDashboardPage`）新增同名开关 → 写入 `ChildSettings.OnlineContentEnabled`；
- 同步时 `ServerSyncService.Apply` 用服务器值覆盖本地，家长在一处改动、另一处自动跟随。

**生效范围**（三个服务的 `OnlineEnabled` 都读这一个字段）：

| 入口 | 判断位置 | 关闭后的表现 |
|---|---|---|
| 宝宝听 / 宝宝看 / 亲子阅 | `ContentService.OnlineEnabled` | 只用内置内容，不发请求 |
| 故事屋 | `IStoryService.OnlineEnabled` | 提示去家长中心打开 |
| 电子课本 | `TextbookService.OnlineEnabled` | 书架提示「请家长打开在线内容」 |

两个条件同时满足才联网：**开关打开** 且 **填了服务器地址**。任何网络失败都静默回退离线，不弹错。

**后台卡片顺带做内容体检**：进入页面时并发拉 `/api/content/audio|video|articles` 与 `/api/books`，把「几组几条 / 几册几页」列出来，家长打开开关前就知道孩子能看到什么，也方便确认课本是否真的渲染进去了。

### 3.33 模拟考试（3-9 年级 · 语数英 21 套卷）

**要解决的问题**：口算只练计算，孩子到期末不知道「整张卷子」是什么样；英语学习只有单词卡，语文则完全没有测验入口。

**做法**：在题库里加「试卷 / 题目」两层，学习天地加一个模式切换，考试流程独立成一个页面。

| 层 | 文件 | 说明 |
|---|---|---|
| 数据表 | `QuestionBank.TableSql` | `exam_paper`（年级/科目/标题/时长）+ `exam_question`（题型/题干/选项/答案/解析） |
| 种子 | `Resources/Raw/questbank/seed_exam.sql` | 21 套 252 题，开头 `DELETE` 保证重灌幂等 |
| 读写 | `QuestionBank.Papers(grade)` / `Questions(paperId)` | 科目用 `CASE` 固定为语文 → 数学 → 英语，不按字母序 |
| 判分 | `Services/ExamGrader.cs` | 全角半角 / 大小写 / 空格 / 句号 / 减号归一化；填空题支持 `|` 分隔的多个等价答案 + 数值等值 |
| 视图 | `ExamViewModel`、`ExamPaperListPage`、`ExamPage` | 一次一题、可前后翻页、最后统一交卷 |

**为什么交卷才批改**：口算是「一题一反馈」，考试需要留出回头检查的空间。`ExamViewModel` 把每题答案存在 `string[]` 里，翻页只换显示不丢答案；最后一道题的按钮变成「交卷」，有空格时先弹确认。

**判断题的选项是造出来的**：库里只存「对 / 错」，视图层统一生成两个 `ExamOption`（`✅ 对` / `❌ 错`），复用同一套选项渲染和单选逻辑，判断题不需要单独的 XAML。

**判分宽容度**（`ExamGrader.Normalize`）：全角字符减 0xFEE0 转半角、去掉空白与中英文引号、`−`/`–`/`—` 统一成 `-`、`×`→`*`、`÷`→`/`、英文转小写、末尾句号去掉。填空题先比字符串，再比数值（`0.75` 与 `0.750`），所以「写对但格式不同」不会冤枉孩子。

**分数是百分制换算**：不设每题分值，`得分 = round(100 × 答对数 / 总题数)`，21 套卷子同一把尺子，跨科目也好比较。

**布局上的坑**：回顾列表用 `BindableLayout` + `VerticalStackLayout`，不用 `CollectionView`——后者在 `ScrollView` 里拿不到有限高度，容易被测量成 0；科目配色用 `Color` 类型的属性而不是字符串，绑定 string → Color 不会自动走类型转换，会静默失效。

### 3.34 儿童心理学 · 自闭症关怀（公益科普页）

**数据口径**（这一页最容易出错的地方，写清楚以免后人误改）：

- 我国官方**只公布自杀死亡率，不公布绝对人数**。5–19 岁用的是《中国卫生健康统计年鉴》分年龄自杀死亡率：2021 年城市 10–14 岁 1.70、15–19 岁 3.34，农村 1.66 / 3.65（每 10 万）。
- 页面里"约 4000 人/年"是**按死亡率 × 年龄段人口粗算的估算值**，正文已标注"不是官方发布的统计值"。不要当成官方数字引用。
- 网上流传的"每年约 10 万青少年死于自杀、每分钟 2 个"与官方死亡率**差一个数量级**，页面里专门辟谣。这条不引入。
- "约六成自杀青少年患有抑郁症"取自科普中国引述的心理回顾研究（不同研究 40%–80%），正文写明区间。
- "24.6%"是《中国国民心理健康发展报告（2019—2020）》的抑郁**检出率**，不等于临床**患病率**，正文有说明。

**实现**：`Helpers/DepressionAssets.cs`（MauiAsset → AppData，`.assetversion` 增量判断）+ `Pages/DepressionPage.xaml(.cs)`。加载逻辑与成长指南 / 儿童心理学同一套：等 handler 就绪再赋 `Source`、加载遮罩、12 秒超时或 `Navigated` 非 Success 切错误面板 + 重试、成功后多次延时压回顶部；安卓侧补齐 `JavaScriptEnabled / AllowFileAccess / AllowFileAccessFromFileURLs`。

**与其他网页页的两处差别**：

1. `OnNavigating` **放行 `tel:`** 并交给 `Launcher.TryOpenAsync`——安卓直接进拨号盘，Windows 无关联程序时静默失败（号码在页面上也写得很大，不影响使用）。其余外链仍一律拦下交系统浏览器。
2. 顶栏把「刷新」换成**「求助」**按钮，`Eval` 点击 `[data-view="data"]` 后跳到电话那一屏。刷新只在失败时才有意义，已由错误面板的「再试一次」覆盖。

**踩到的坑**：切换标签时一整屏会被 `.hidden` 隐藏，文档高度骤变，Chromium 的**滚动锚定**会把视口粘在原来的元素上，表现为切过去停在半中间而不是顶部。修法是 `html/body { overflow-anchor:none }`，再配合 `go()` 里的三次置顶（0 / 30ms / 180ms），原生侧 `ScrollTopAfterSwitchAsync` 再从 80/240/500ms 补压三次。用无头 Chrome 做过串行断言：从 1500 处依次点 data → care → know，三次的 `scrollY` 都是 0。

**调试入口**：`KS_START_PAGE=depression`（仅 Debug）。

### 3.37 游戏乐园合并为一个入口

**问题**：首页原本并列两个入口——`GamesHubPage`（小游戏乐园，原生小游戏 + 难度 + 家长开关）与 `PlaylandPage`（游戏乐园，15 款网页游戏的 WebView 大厅）。两者功能重叠，顶栏一个主题渐变、一个深蓝，看起来像两个产品。

**改法**：

- 首页只保留 `AddBuiltIn("🎮", "游戏乐园", …)`，删掉 `🕹️ 游戏乐园` 那一行；家长开关的判断从 `"小游戏乐园"` 同步改为 `"游戏乐园"`（`OnboardingPage` 的文案一并改）。

- `PlaylandPage` 构造签名改为 `PlaylandPage(string gameFile = "index.html", string title = "🎮 小游戏")`，`ResolveUrl()` 把 `pages/xxx.html` 拼到已释放目录下；不传参时仍加载大厅，`SplashPage` 的 `KS_START_PAGE=playland` 不需要改。

**注意**：`WebGames` 与 `PlaylandAssets.Files` 是两份手工维护的清单，增删网页游戏时必须同时改两处，否则会出现"大厅里有卡片但打不开"或"包里有游戏但大厅看不到"。

### 3.38 Windows 安装包与桌面右键菜单

**两条发布路线**（刻意并存）：

| 产物 | 生成方式 | 是否写注册表 | 桌面右键 |
|---|---|---|---|
| `KidsSafeDesktop-<v>-win.zip` | `release.bat`（`dotnet publish` + `Compress-Archive`） | 否 | **没有** |
| `KidsSafeDesktop-<v>-setup.exe` | `build-installer.bat`（Inno Setup 6） | 是（仅 HKCU） | **有** |

**安装器要点**（`Installer/KidsSafeDesktop.iss`）：

- `PrivilegesRequired=lowest`，装到 `{localappdata}\Programs\KidsSafeDesktop`，不弹 UAC。
- 隐私政策：`LicenseFile=PrivacyPolicy.txt`，该文件由 `Scripts/export-privacy.ps1` 从 `Models/ComplianceContent.cs` 的 `PolicySections` 抽取，保证安装界面与应用内「隐私政策」页**是同一份文字**；`[Messages]` 把按钮改成「我接受这份隐私政策」。
- 官网链接：`[Code]` 的 `InitializeWizard` 在**欢迎页** `WelcomeLabel2` 下方加两个 `TNewStaticText`——一个蓝色带下划线的 `ShellExec` 链接指向 `https://kids.siguangblog.cc/`，一个灰色两行提示；`CurPageChanged` 在完成页再追加一次纯文本地址。
  - 为什么不放许可页：许可页正文区被隐私政策占满，`LicenseMemo` 下方紧接着就是「我接受」单选按钮，再插文字会压到按钮上。欢迎页下半部分是空的，位置稳定。
  - 灰色提示那行必须 `AutoSize := False` + `WordWrap := True` + `Width := WelcomeLabel2.Width`，否则按内容自动撑宽，横向溢出窗口右边被裁掉。
- 桌面右键：写 `HKCU\Software\Classes\DesktopBackground\Shell\KidsSafeDesktop`（`MUIVerb` / `Icon` / `Position=Top`）+ `\command` 默认值，主键带 `uninsdeletekey`，卸载即清；对应 `[Tasks] desktopmenu`，用户可取消勾选。Windows 11 收在「显示更多选项」里，安装页文案已说明。
- `[Files]` 排除四类：`publish\*`、`KidsSafeDesktop.exe.WebView2\*`、`*.pdb`、`*.xml`。
  - `publish\*` 最容易被漏掉：`dotnet publish -r win-x64 --self-contained` 会把同一套自包含产物**同时**写进 `win-x64\` 和 `win-x64\publish\`，而 `recursesubdirs` 会把子目录一起收进来，安装包体积直接翻倍。
  - `KidsSafeDesktop.exe.WebView2` 是本机运行留下的缓存（约 9MB），`*.pdb` 是调试符号，`*.xml` 是 XML 文档注释，终端用户都用不到。

**中文语言文件要随项目一起提交**：

Inno Setup 6 自带的 29 种语言里**没有中文**（中文属非官方翻译，不在 `compiler:Languages\` 下），只写 `MessagesFile: "compiler:Languages\ChineseSimplified.isl"` 会直接 `Compile aborted`。因此把 `Installer/ChineseSimplified.isl` 收进仓库，脚本用相对路径引用，换机器构建不依赖 Inno 安装目录。文件来自 <https://github.com/kira-96/Inno-Setup-Chinese-Simplified-Translation>，UTF-8 无 BOM，Inno 6.5.0+ 语法。

**踩到的坑**：

1. `.ps1` 必须存成 **UTF-8 with BOM**，否则 PowerShell 5.1 按 GBK 解码，中文全变乱码并且语法直接报错（`UnexpectedToken`）。
2. `.bat` 保持纯 ASCII（cmd 用 936 代码页解析），中文提示一律放在 ps1 里——与 `release.bat` / `deploy.bat` 同一约定。
3. **不要加 `PrivilegesRequiredOverridesAllowed=dialog`**：它会让安装程序一启动就先弹「为所有用户安装 / 仅为我安装」，多一步，而且选「所有用户」会去写 HKLM、要求提权，直接破坏免提权的设计。
4. **必须显式写 `DisableWelcomePage=no`**：默认（`auto`）会把欢迎页跳过，向导直接从许可协议开始，加在欢迎页上的官网链接就等于没有。
5. 消息键名是 `LicenseLabel` 和 **`LicenseLabel3`**（不是 `LicenseLabel2`）。`LicenseLabel` 是页头那句、`LicenseLabel3` 是正文上方那句，两处都要覆盖，否则会出现两句意思重复的引导语。
6. 覆盖 `LicenseAccepted` / `LicenseNotAccepted` 时别忘了补回 `(&A)` / `(&D)` 加速键，否则键盘操作不了单选按钮。
7. `build-installer.bat` 末尾有 `pause`。**从管道或非交互环境调用时必须先 `set NO_PAUSE=1`**，否则进程卡在 `pause` 上，而输出又被 `tail` 之类缓冲住，看起来像"编译卡死"。
8. 本机验证静默安装时，`/LOG=` 不能指向**还不存在**的目录——Inno 会在创建日志前就退出，返回 exit code 1 且不写任何日志，很容易误判成"安装包坏了"。
9. 安装包本身不签数字证书，SmartScreen 首次运行会提示"未知发布者"；对外分发前建议补签名。

## 6. 已知限制

- 服务端鉴权为共享令牌，适合家庭/局域网；公网部署务必加 HTTPS 反代与账号体系。
- 天气依赖第三方免费接口，偶发限流/不可达时主页自动隐藏天气卡片。

  未安装时页面会显示指引（见 3.21 操作帮助中心）。
- 音频为 16kHz / 16bit 单声道 WAV 以便兼顾体积与兼容性；如需更高音质可调
  `Docs/tools/generate_kids_audio.py` 的 `SR` 并重新生成（体积同步增加）。
