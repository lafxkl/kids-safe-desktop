★★★ 重要结论（2026-11-04 实测）★★★
平台的指纹输入框**只接受带冒号的 95 字符格式**；
把冒号去掉的 64 字符格式（无论大小写）都会被前端拦下，
红字提示「请输入正确的 SHA256 证书指纹」，无法保存。
所以：**不要去改指纹**。平台里已保存的那一行如果和上面这行
逐字符相同，就说明登记是对的（截图中已核对：完全一致）。

代码侧已核实（反编译 push-10.0.39.302.aar）
- com.hihonor.push.sdk.x.a(Context) 组装 RequestHeader 时：
  · appId  = PackageManager 读 meta-data "com.hihonor.push.app_id"
             → Bundle.get() + String.valueOf()，清单里被 aapt2 编成 int
               也能正确拿到 "104600830"，不是问题
  · packageName = Context.getPackageName()
  · certificateFingerprint = com.hihonor.push.sdk.d.a() 计算：
             SHA256(签名字节) → 逐字节 toHexString(b & 0xFF)
             → toUpperCase(ENGLISH) → 不足两位补 0 → 直接拼接，**不带冒号**
  这三项与平台登记值一一对应，客户端没有可再改的地方。

10202 根因（2026-11-04 11:29 平台截图确认）
应用列表显示：
  应用包名 com.companyname.kidssafedesktop / APPID 104600830  ← 都正确
  上架状态：准备提交
  已获得权限：0
  驳回权限：0
即：推送服务权限既未通过、也未驳回 → 应用信息还没在推送服务端生效，
服务端查不到这条 APPID 的生效绑定，于是统一回 10202
（错误码文案只写「包名或指纹不一致」，容易把人带偏）。

处理顺序：
1. 该行末尾点「申请权限」，勾选推送服务并提交；
2. 看「申请记录」里的审核状态，等通过（已获得权限变成 1）；
3. 权限通过后再到应用内诊断页点一次「重新申请 token」。
注意：荣耀推送要求企业开发者账号，个人开发者账号可能无法获得该权限。
