# 服务端账号体系（KidsSafeServer 1.3）

> 目的：把「一个固定密码 + 一个固定令牌 + 一份全局配置」的老结构，换成
> **家长账号 + 配对码 + 每账号独立配置**。
>
> 触发点：老版本任何人只要知道 `1234` 就能改全家的配置，令牌 `kids-admin-token` 写死在代码里，
> 而且一台服务器只能服务一个家庭。加了账号之后，同一台服务器可以放多个家庭的数据，
> 孩子设备也不再需要知道家长密码。

---

## 一、三条登录路径

| 谁 | 用什么 | 拿到什么 | 能做什么 |
|---|---|---|---|
| 家长（网页/家长端） | 账号 + 密码 | 家长令牌（30 天） | 读配置、写配置、生成配对码、改密码、管理设备 |
| 儿童设备 | 6 位配对码（10 分钟、用一次即废） | 设备令牌（365 天） | **只读**配置，`PUT /api/settings` 返回 403 |
| 升级过渡 | 老家长密码 `AdminPin` | 家长令牌 | 仅在「一个账号都没注册」或 `Auth:AllowPinLogin=true` 时可用 |

配对码是这套设计的关键：家长不必把密码告诉孩子，孩子在平板上输 6 位数字就能同步，
但改不了任何东西。设备在后台可以随时「移除」，令牌立刻作废（`Resolve` 时找不到设备记录即拒绝）。

## 二、数据落盘

```
data/
├─ accounts.json      账号数组 + bootstrapAccountId
├─ profiles/
│  ├─ u_9547bfa1.json  每个账号一份 ManagedProfile
│  └─ …
├─ profile.json       老的单账号配置（未注册时的 default 账号用）
└─ auth.key           自动生成的 HMAC 签名密钥（32 字节）
```

- **口令**：PBKDF2-HMAC-SHA256，10 万次迭代，16 字节随机盐，32 字节输出；
  比较用 `CryptographicOperations.FixedTimeEquals`，防计时攻击。
- **令牌**：`v1.<base64url(payload)>.<base64url(HMAC)>`，载荷含 `sub/name/role/ver/dev/iat/exp`。
  不引 JWT 包，三十行 HMAC 就是 HS256 的全部语义。
- **改密码即踢人**：`Account.PasswordVersion` 每次 +1，令牌里的 `ver` 对不上就 401。
  设备令牌 `ver=0` 不参与这个校验，改密码不会把孩子设备踢下线。
- **`bootstrapAccountId`**：第一个注册的账号。老客户端手里那个固定令牌映射到它，
  所以升级服务端后，已经装好的儿童端不用重新配对。

## 三、接口

| 接口 | 说明 |
|---|---|
| `GET /api/auth/status` | 公开。是否已有账号、能否注册、老密码通道是否还开 |
| `POST /api/auth/register` | `{username,password,displayName}`；第一个账号为 owner，并复制老配置 |
| `POST /api/auth/login` | `{username,password}` / `{code,device}` / `{pin}` 三种体，401 失败、429 限流 |
| `GET /api/auth/me` | 校验令牌，返回 `canWrite`（设备为 false） |
| `POST /api/auth/password` | `{oldPassword,newPassword}`，成功后旧令牌全部失效 |
| `PUT /api/auth/profile` | 改家庭显示名 |
| `GET /api/auth/paircode` | 生成 6 位配对码 |
| `GET/DELETE /api/auth/devices/{id}` | 查看 / 移除已配对设备 |
| `POST /api/auth/logout` | 无状态，仅给前端一个收尾动作 |

令牌可以放查询串 `?token=`（老客户端就是这样），也可以放 `Authorization: Bearer`。
`/api/settings` 与 `/api/watch` 的语义没变，只是**按账号隔离**。

限流：同一 IP 连续失败 5 次锁 60 秒（`LoginThrottle`，内存态，重启归零）。

## 四、网页

- **`wwwroot/login.html`（新增）**：登录 / 注册两个页签，左侧品牌区在手机端自动收起。
  首次使用（`hasAccounts=false`）会直接切到注册页并给出提示；注册成功后把
  `adoptedLegacyProfile` 告诉家长（原有配置已迁移）。
  登录成功写 `localStorage.ks_token`（沿用老键名）+ `ks_user`，跳 `index.html`。
- **`wwwroot/index.html`**：
  - 登录卡撤掉，无令牌直接 `location.replace("login.html")`；
  - 进后台先打 `/api/auth/me`，令牌过期或被改密码就回登录页；
  - 新增「👤 账号与设备」卡：家庭名称、账号角色、生成配对码（带倒计时）、
    已配对设备列表（可移除）、修改密码；
  - 设备令牌进来时，保存按钮变灰并提示「设备只读」。
- **`wwwroot/docs.html`**：配置项、目录结构、接口清单、安全须知、FAQ 全部同步。

## 五、客户端（KidsSafeDesktop / KidsSafeParent）

`IServerSyncService.LoginAsync(string? username, string secret)`：

- `username` 为空 → 发 `{pin: secret}`，服务端按「配对码 → 老密码」顺序解释；
  这条路径**老客户端零改动**可用，只是现在该填的是配对码。
- `username` 非空 → 发 `{username,password}`，拿到可写令牌。

`AccountPage` 与 `ParentDashboardPage` 各加了一个「家长账号（可留空）」输入框，
密码框占位符改成「密码 或 6 位配对码」，并加了一行说明：配对码只能同步、不能修改。

## 六、安全边界（别高估）

- 仍然是 **HTTP**，局域网内明文。要公网用就自己挂 HTTPS 反代，并且别做端口映射。
- 没有邮箱找回、没有二步验证、没有审计日志；忘记密码只能本机改 `data/accounts.json`。
- 账号是「家庭内共享」模型，没有孩子档案、没有按孩子区分的权限。
- `Auth:AllowRegister` 默认 `true`：同网段的其他人也能注册一个账号（各自的数据是隔离的，
  但会看到同一台服务器）。家里用建议注册完就改成 `false`。

## 七、升级注意

1. 直接覆盖 exe / 目录即可，`data/profile.json` 会原样保留。
2. 打开后台 → 被引导到注册页 → 注册第一个账号 → 老配置自动复制到
   `data/profiles/{新账号}.json`，老设备继续用原令牌。
3. 注册后老密码 `1234` 自动失效；家里还有没升级的旧客户端时，
   要么给它生成配对码，要么临时把 `Auth:AllowPinLogin` 设为 `true`。
