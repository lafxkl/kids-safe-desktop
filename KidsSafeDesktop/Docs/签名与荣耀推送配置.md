# 签名证书与荣耀推送配置

> 本文含 keystore 口令，属于机密材料，不要提交到公开仓库、不要截图外发。

## 一、签名证书（v1.8 起启用）

| 项 | 值 |
|---|---|
| keystore 文件 | `Keys/kidssafe.keystore` |
| 别名 alias | `kidssafe` |
| 口令（store / key 相同） | `wlYoOMm78npjB0J9RR6GEL4w` |
| 有效期 | 2026-11-04 ~ 2056-10-27（30 年） |
| DN | `CN=KidsSafe Desktop, O=KidsSafe, L=Beijing, ST=Beijing, C=CN` |

**SHA-256 指纹**（荣耀平台填这个，去掉冒号）：

```
E05270932C2F6FED2A5ECF3389BC45B3B0D206CAACDA11C8A939E120AD55CD35
```

带冒号形式（便于核对）：

```
E0:52:70:93:2C:2F:6F:ED:2A:5E:CF:33:89:BC:45:B3:B0:D2:06:CA:AC:DA:11:C8:A9:39:E1:20:AD:55:CD:35
```

**SHA-1 指纹**（部分平台要 MD5/SHA1）：

```
0AB76BECD3108E752C3F9419A17097609D406931
```

签名配置在 `Signing.props`（`KidsSafeDesktop.csproj` 末尾 Import），**Debug 与 Release 共用同一证书**——否则会出现「正式包能收推送、测试包 10202」。

### ⚠️ 这个文件必须备份

keystore 是应用的长期身份。丢失后：
- 已安装的设备**无法覆盖升级**，只能卸载重装（本地数据全丢）；
- 应用商店无法发布后续版本（商店不接受签名变更，除非走「签名重置」且要求很严）。

建议立刻复制一份到 U 盘或私有云，连同本文件一起。

### 更换签名的影响

**从 v1.7 及更早版本升级到 v1.8，必须先在手机上卸载旧版**，否则会提示「应用未安装 / 签名冲突」。卸载会清空应用内数据（昵称、家长密码、排行榜、已允许的应用列表），需要重新设置一次。

## 二、荣耀推送 10202 的处理

`10202 = 证书指纹或包名与开发者服务平台信息不一致`（荣耀官方错误码文档）。

v1.7 真机日志实测：

```
token:10202:parameter error
```

原因是当时 APK 由 **Android 调试证书**签名（`CN=Android Debug`，SHA256 以 `F3:86:79:5E…` 开头），与平台登记不一致。

### 要在荣耀开发者服务平台做两件事

**1. 填包名**

```
com.companyname.kidssafedesktop
```

这个包名是 MAUI 模板默认值，如果控制台里填的是别的（或注册应用时随手写的），必然 10202。
如果要改成正式包名（如 `com.kidssafe.desktop`），告诉我，我改 `ApplicationId` 后重新出包——但同样需要卸载重装，并且控制台要同步改。

**2. 添加证书指纹**

- 位置：荣耀开发者服务平台 → 我的应用 → 选择应用 → 应用信息 → **证书指纹（SHA-256）**
- 值：上表的 `E05270932C2F6FED2A5ECF3389BC45B3B0D206CAACDA11C8A939E120AD55CD35`
- 支持多个签名时全部添加（例如以后换证书，旧指纹要保留一段时间做过渡）

改完通常几分钟内生效。**v1.9 起诊断页有「🔁 重新申请推送 token」按钮**，按一下即可重新校验，不必杀进程重开应用（荣耀侧有频控，按钮内置 30 秒间隔限制）。仍失败的话，到「家长设置 → 诊断日志」看「最近错误」的新错误码。

### 真机实测记录

| 版本 | 是否支持 | 错误 | 说明 |
|---|---|---|---|
| v1.7 | 否（误报） | `10202` | support 键类型 bug，且 APK 由调试证书签名 |
| v1.8 | 是 ✅ | `10202` | 签名已换正式证书，但平台尚未登记指纹 |
| v1.9 | 是 ✅ | 待登记后复测 | 增加「重新申请 token」按钮 |

### 其他可能遇到的码

| 码 | 含义 | 处理 |
|---|---|---|
| 10202 | 证书指纹或包名不一致 | 见上 |
| 8001000 / 8002008 | 设备不支持荣耀推送 | 必须是荣耀设备，且系统含荣耀推送服务 |
| 8001002 | 清单未配置 appId | `AndroidManifest.xml` 的 `com.hihonor.push.app_id` |
| 10211 | 该设备今天注册 token 达上限 | 次日再试 |
| 10214 | 请求过于频繁 | 稍后重试，不要频繁调用 |

## 三、当前推送链路状态

已打通（客户端）：

1. `MainActivity.OnCreate` → `HonorPush.Start()`
2. JNI → `com.kidssafe.push.HonorPushBridge.start()`
3. `HonorPushClient.checkSupportHonorPush()` → `init()` → `getPushToken()`
4. 结果写入 `SharedPreferences("honor_push")`，C# 侧读取
5. `KidsHonorMessageService` 接收 token 变更与透传消息

**未做**：收到消息后弹系统通知。Android 13+ 需要 `POST_NOTIFICATIONS` 运行时权限，儿童桌面上不适合弹权限框，所以当前只落盘（`LastMessage`）。要不要做需要单独决定。
