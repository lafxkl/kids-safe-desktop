## 服务端 1.3 — 2026-11-12 家长账号体系（登录页 / 配对码 / 配置按账号隔离）

> 服务端版本独立于 App 版本。这次只动 `KidsSafeServer`，客户端是兼容性改动（多一个可选「家长账号」输入框）。
> 详细设计见 `Docs/账号体系.md`。

### 一、从「一个密码」到「家长账号」

老结构：`AdminPin=1234` 明文比对，登录后下发写死的 `kids-admin-token`，全服务器只有一份配置。
问题很直接：知道 1234 就能改全家设置；一台服务器只能服务一个家庭；改密码等于改配置中心。

现在：

| 谁 | 凭证 | 权限 |
|---|---|---|
| 家长 | 账号 + 密码（PBKDF2，10 万次迭代） | 读写配置、生成配对码、改密码、移除设备 |
| 儿童设备 | 6 位配对码（10 分钟、一次性） | **只读**，`PUT /api/settings` 直接 403 |
| 老客户端 | 固定令牌 / 老密码 | 过渡期继续可用，映射到第一个注册的账号 |

- 第一个注册的账号是 `owner`，注册时把 `data/profile.json` 复制成 `data/profiles/{id}.json`，
  并把 `bootstrapAccountId` 指向它 —— 已经装在孩子平板上的旧版本**不用重新配对**。
- 改密码让 `PasswordVersion+1`，此前签发的家长令牌全部失效；设备令牌不受影响。
- 同一 IP 连续失败 5 次锁 60 秒，挡脚本撞密码。

### 二、新增登录页 `login.html`

- 登录 / 注册两个页签，首次使用（还没有账号）自动切到注册页；
- 手机端左侧品牌区收起，登录框占满一屏，输入框 16px 避免 iOS 缩放；
- 老密码通道收进「用旧版家长密码登录」折叠区，只有服务端还开着才显示；
- 已登录用户访问登录页会直接跳后台（先打 `/api/auth/me` 验一次令牌）。

`index.html` 的登录卡撤掉，改成无令牌即跳转；后台新增「👤 账号与设备」卡：
家庭名称、账号角色、生成配对码（带剩余时间倒计时）、已配对设备（可移除）、修改密码。
设备令牌进入后台时，保存按钮变灰并提示「设备只读」。

### 三、长轮询按账号分桶

`WatchSignal` 原来只有一个全局版本号，A 家保存配置会把 B 家的设备也唤醒。
现在每个账号一个 `Bucket`，`Pulse(accountId)` / `VersionFor(accountId)`；
`/api/watch` 只等自己账号的版本，`/api/health` 仍返回累计次数。

### 四、客户端改动（向后兼容）

`IServerSyncService.LoginAsync(string? username, string secret)`：
账号留空 → 仍发 `{pin}`（服务端按配对码 → 老密码解释），老客户端行为不变；
填了账号 → 发 `{username,password}`，拿可写令牌。
`AccountPage` 与 `ParentDashboardPage` 各加一个「家长账号（可留空）」输入框，
密码框占位符改为「密码 或 6 位配对码」，并说明配对码只能同步、不能修改。

### 五、接口与配置

- 新增：`/api/auth/status|register|me|password|profile|paircode|devices|logout`
- 配置：`Auth:AllowRegister`（默认 true）、`Auth:AllowPinLogin`（null=智能）、`Auth:Secret`（留空自动生成 `data/auth.key`）
- 服务端版本 `1.2 → 1.3`；`docs.html` 的配置项、目录结构、接口表、安全须知、FAQ 全部同步。

### 六、验证

- `KidsSafeServer` 0 警告 0 错误；端到端脚本跑通 15 个用例：
  注册 → me → 读/写配置 → 配对码 → 设备登录 → 设备写配置 403 → 配对码复用失败 →
  老密码自动关闭 → 密码登录 → 5 次错误触发 429 → 设备列表 → 改密码后旧令牌 401 → 老固定令牌仍可用。
- 孩子端 / 家长端 / 共享库 Windows 编译 0 错误。
- **未验证**：真机上的配对码输入体验；多账号同时在线的长轮询隔离（只有单元级推演）。

### 一、家长课从 4 节扩到 10 节

原来「给家长看」只有 4 节，全部围绕「父母在外、孩子在家」这个场景（怎么解释外出、15 分钟电话怎么打、
哪些信号需要专业帮助、怎么和爷爷奶奶配合）。这次补的是**日常养育**这一层——孩子在身边时每天都会遇到的事：

| 新课 | 一句话 | 讲什么 |
|---|---|---|
| 🤲 少做一点，孩子反而长得更好 | 把那 80% 不必要的插手放下 | 灾难性思维、共情不等于同理、一个错要犯 3–7 次才学会、允许家里乱一点 |
| 💬 孩子「不听话」时，先接情绪再讲道理 | 先被理解，才愿意被教导 | 前额叶没长好、长篇大论会被「屏蔽」、麦拉宾 55/38/7、带他自己说出结论 |
| 🌱 如果孩子只是个普通孩子 | 可以接受现在普通，别认定将来只能普通 | 「普娃」的尺子会移动、投入不等于产出、发展有时间差、从「喜欢什么」里找天赋 |
| 🎯 把「你要努力」换成今天能做完的一件小事 | 一次只定一个目标 | 手表定律、目标要够得着、时间表一起定一起做、没做到先听原因 |
| 🧭 他现在这个年纪，真正在意什么 | 不是变坏了，是到了另一个阶段 | 1-3 / 4-6 / 7-9 / 10-12 / 13-18 五段，每段写「他为什么变了 + 家长该退到哪一步」 |
| 🪁 先懂孩子，再谈教育 | 孩子不是白纸，是带着图纸的种子 | 陈鹤琴的儿童心理：好游戏、好奇、好模仿、喜欢成功、喜欢被称赞（但不可滥） |

- 每节仍然 5 段，最后一段是「这周就能做的一个动作」（例如：选一件你平时一定会代劳的事，这周只在旁边看着）。
- 家长课 4 → 10 节，与孩子侧 10 节对齐；`CareLessonPage` 的「N 节」是读列表长度算的，不用改数字。
- `Pages/CareLessonPage.xaml.cs` 的家长引导语、`Pages/CareCenterPage.xaml` 的「给家长看」副标题
  从「怎么打电话、怎么看出来」改为「怎么说话、怎么放手」——原来那句只概括了 4 节里的 2 节。

### 二、内容口径：为什么不是照搬原文

- **不照搬标题**：原文「优秀的孩子都是管出来的」这类因果句，放在留守家庭语境里会变成指责（孩子不优秀＝没管好），
  一律改成描述行为与动作的中性说法。
- **不收制造羞耻感的做法**：36 计里的「激发计」用嫉妒心刺激孩子、「冷淡计」长期不理，与小课堂「不制造羞耻感」的基调冲突，未采用。
- **去掉分数与排名叙事**：关爱中心面向的是父母长期不在身边的孩子，成绩叙事会放大焦虑，新课只留「先关心人，再关心分数」。
- **不重复已有内容**：10 篇里的《教育孩子 36 计》v1.19 已做成独立页面（`Resources/Raw/edu36`，按 6 类场景可筛），
  《30 个培养孩子的细节》正文是长图、只取到导语，**没有凭标题编造条目**，两篇都未进小课堂。
- 所有新课没有新增求助渠道、没有引入原文的课程或商品引导。

### 七、心灵感应魔法（第 20 款小游戏）

**心里想一个数，回答 6 次「在 / 不在」，游戏把它猜出来。内核是二进制，
玩法解析见 `Docs/心灵感应魔法-机制解析.md`**

#### 1. 机制

- 观众想一个 1~60 的数 → 依次看 6 张卡片 → 每张答「在 / 不在」→ 6 个回答后报出答案。
- 第 k 张卡片的代号是 2^(k-1)（1、2、4、8、16、32），内容是「二进制第 k-1 位为 1」的数字集合。
- 把回答「在」的卡片代号相加即为答案；二进制表示唯一 ⇒ 6 个回答与数字一一对应，**必然猜中**。
- 取 60 而非 63 是障眼法：63 是 2^6−1，容易被人看出规律。

#### 2. 实现

- `Models/MindReadData.cs`：`MindReadLevel`（15 / 31 / 60）、`MindReadEngine`（位权表、`CardCountFor` / `CardsFor` / `Reveal` / `Decompose` / `SumText` / `IsPlausible` / 讲解文案）。不依赖 MAUI，可单独放进控制台工程穷举自检。
- `Pages/MindReadGamePage.xaml(.cs)`：四个阶段叠在同一页靠 `IsVisible` 切换（开场选等级 → 逐张卡片 → 揭晓 → 揭秘），避免页面跳转重放揭晓动画。
- `Helpers/StarfieldDrawable.cs`：星空背景，固定随机种子（否则切页像下雪）。
- 卡片用 `Grid` 动态行列而非 `FlexLayout`：4 列 60×48 / 22 号字（8、16 个数字），5 列 48×42 / 18 号字（29、30 个数字，`5×48+4×7=268` 可进 320 宽屏）。

#### 3. 三处产品取舍

- **卡面不显示代号**。标了「代号 32」孩子自己就能算，魔术当场失效；代号只在揭秘页出现。
- **答不上来不算错**。六张全「不在」或加出来超过上限时，不显示错数字，而给 🤔 +「可能有一张记混了」+「🔄 再试一次」。另设「🤔 我忘了想的什么」出口——6 轮问答里忘掉原数字，3~6 岁孩子比成人想象的高得多。
- **揭秘是主要价值**。揭晓页给「🔍 这是怎么做到的？」，用「代号相加」的说法讲（刻意不以「二进制」为主词），当场摆出 `32 + 4 + 1 = 37`，六张卡按在 / 不在染色，最后引导孩子给爸妈表演。

#### 4. 接入与结算

- `GameType.MindRead`、`GameCatalog` 第 20 条（🔮 心灵感应魔法 / #7C5CFF）、`GamesHubPage.PageFor` 分支。

### 一、围棋小课堂（原生）

- `Models/GoEngine.cs`：9 路规则引擎。`Play()` 先在副本上试算（`Simulate`），确认不是禁入点、不违反打劫，再落到真棋盘上；提子在副本里完成后再统计提子数，避免「先落子后回滚」导致的脏状态。

## v1.11 — 2026-11-04

**修诊断页「App ID：(清单未配置)」误报**

- 根因：`android:value="104600830"` 全是数字时，aapt2 把它编成 **int** 而不是 String（`aapt2 dump xmltree` 里 `value=104600830` 没有引号，而同节点的 `name="…"` 有）。`Bundle.GetString` 对 int 返回 null，于是诊断页误显示「未配置」。
- **排查时请注意：这一行与 10202 无关。** 荣耀 SDK 内部用 `String.valueOf(bundle.get("com.hihonor.push.app_id"))` 读取，int 会正常转成 `"104600830"`，推送链路一直是通的。
- `AppSignature.ReadMeta()`：先 `GetString`，失败再 `Bundle.Get` + `Java.Lang.Integer.IntValue()` / `ToString()`；新增 `HonorSdkVersion` 显示（读 AAR 合并进清单的 `com.hihonor.push.sdk_version`）。
- 顺带交叉验证 SDK 的指纹算法：`SHA256(Signature.toByteArray())` 逐字节十六进制，与本地 `keytool` / `openssl` / `GET_SIGNING_CERTIFICATES` 四处结果一致 → **指纹这一路已完全排除**。
- 排除「生效延迟」：指纹 06:40 保存、10:49 仍 10202，4 小时足够同步。
- 版本号 `1.10 → 1.11`、`ApplicationVersion 11 → 12`（versionCode 12）。签名不变（`E0:52:…:CD35`），可覆盖安装。

1. 改 `MauiIcon` 的前景/背景图后，只改 csproj 不会重新生成图标，必须删掉 `obj/<配置>/<TFM>/resizetizer` 再建。

3. 各页面 `LauncherGridView` 的**横向 Padding 必须一致**（当前统一 18），否则可用宽度差几像素，两页图标会差半个像素级。
