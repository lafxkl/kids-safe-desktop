# 增量更新方案（按 dll 打补丁）

> 目标：改一个按钮、修一个文案、调一段逻辑，家长**不用再下载 100 MB 的安装包**，
> 只拉几 MB 的 `dll`，下次打开就是新版。
> 适用范围：Windows（主）、Android（受限，见第二节）、Linux/Qt（不在本次）。
>
> 一句话结论：**Windows 能真增量；Android 只能增量到「托管程序集」这一层，
> APK 里的原生库、清单、权限永远得整包。** 这一点绕不过去，方案按这个事实设计，
> 而不是假装三端一样。

---

## 一、三端能力矩阵（先看这张表，后面都是它的展开）

| 端 | 应用形态 | 能增量替换 | 不能增量替换 | 落地方式 |
| --- | --- | --- | --- | --- |
| **Windows** | 自包含 MAUI，免打包（`WindowsPackageType=None`），装在 `%LOCALAPPDATA%\Programs\KidsSafeDesktop`（**当前用户可写，不需要 UAC**） | `KidsSafeShared.dll`、`KidsSafeDesktop.dll`（除 apphost）、`Assets/`、`Resources/` 里的内容与图片 | `KidsSafeDesktop.exe`（apphost，运行中锁定）、`coreclr.dll` 等运行时本体 | 下载 → 验签 → 暂存 → **重启时由 `KidsSafeUpdater.exe` 落盘**（备份 + 回滚 + 重启） |
| **Android** | 签名 APK（ sideload 分发，不走应用商店） | 托管程序集 `*.dll`（**预加载覆盖**，见第三节）、内容 JSON | APK 内的原生 `.so`、`AndroidManifest`、权限、图标、`ApplicationId` | 补丁落 `files/patches/<版本>/`，下次冷启动在**任何业务代码之前**把 dll 预加载进默认 ALC |
| **Linux / Qt 版** | 单二进制 + `assets/`（deb） | `assets/`、`assets/codelab/*.json`、`assets/playland/` | 二进制 `kidssafe` | 二进制只有 3–5 MB，整包替换比做增量更划算；deb 走 `apt` |

**为什么 Windows 上「只更新 dll」几乎等于「更新整个应用」**：本工程从一开始就把
界面与业务整体放在 `KidsSafeShared`（`Pages / ViewModels / Services / Models / Helpers`），
壳工程只留 `App.xaml`、`MauiProgram`、`Platforms`、`Resources`。
所以 `KidsSafeShared.dll` 一个文件就是 95% 的代码量，XAML 也在里面（`MauiXamlInflator=SourceGen`
把 XAML 编译进程序集）。这就是这次能做成的前提——不是临时改造出来的。

**为什么不能连 apphost 一起换**：`KidsSafeDesktop.exe` 是 .NET 的 apphost，
运行中文件被映射锁定；换它等于换整个进程，那就不是增量了。
所以补丁清单只允许替换 `*.dll` 与资源，**永远不允许替换 `*.exe`**（校验时直接拒绝，
见第五节）。

## 二、补丁单位：文件级，不做二进制差分

对比两种做法：

| 方案 | 补丁体积 | 复杂度 | 结论 |
| --- | --- | --- | --- |
| **文件级全量**（本方案） | 改动文件的完整大小，典型 1–3 MB | 低：算 SHA-256、比对、复制 | ✅ 采用 |
| 二进制差分（bsdiff / xdelta3 / courgette） | 几十 KB–几百 KB | 高：要在客户端内置差分算法、按「旧版本 × 新版本」组合准备补丁、任一侧不匹配就退化 | 暂不采用 |

理由：本应用的单次改动集中在 `KidsSafeShared.dll`（约 2–3 MB，gzip 后 1 MB 出头），
在家庭宽带/4G 下都是一两秒的事；而差分会把「发一个版本」变成「发 N 个版本的补丁矩阵」，
维护成本远高于省下的那 1 MB。**接口已经留好**：清单里的 `url` 指向哪个文件由服务端决定，
将来要上差分，只改下载与还原那一层，客户端其余逻辑不动。

## 三、补丁清单与签名

### 3.1 为什么是「两个文件」而不是「一个带 signature 字段的 JSON」

JSON 规范化（key 顺序、空白、数字格式）在不同序列化器之间不一致，
「签名时算一遍、验签时再算一遍」只要有一处空格不同就验不过，
这是自更新系统最常见的一类线上事故。

所以采用**原始字节签名**：

```
patches/windows/current/manifest.json   ← 清单本体，逐字节原样签名
patches/windows/current/manifest.sig    ← 对上一行文件的字节做的 RSA-4096 / PSS-SHA256 签名（base64）
patches/windows/current/files/...       ← 补丁文件，路径与清单里的 path 对应
```

客户端拿到 JSON 的**原始字节**先验签，通过后才解析——顺序不能反，
否则解析器就先吃到了不可信输入。

### 3.2 清单格式

```json
{
  "schema": 1,
  "platform": "windows",
  "channel": "stable",
  "version": "1.21",
  "versionCode": 22,
  "minHost": "1.20",
  "base": ["1.20"],
  "issuedAt": "2026-11-23T08:00:00Z",
  "expiresAt": "2027-02-21T00:00:00Z",
  "notes": "修复积木编程在部分机器上启动失败的问题",
  "files": [
    { "path": "KidsSafeShared.dll", "sha256": "9f2c…", "size": 2715648 },
    { "path": "Assets/updates/notice.json", "sha256": "1a77…", "size": 812 }
  ],
  "removed": ["KidsSafeShared.resources.dll"]
}
```

字段含义（客户端会逐条校验，不合规直接拒绝整份清单）：

| 字段 | 校验规则 | 不合规的后果 |
| --- | --- | --- |
| `schema` | 必须等于 1 | 拒绝（旧客户端看不懂新格式，宁可整包） |
| `platform` | 必须等于当前平台（`windows` / `android`） | 拒绝（防止把 Windows dll 装到手机上） |
| `version` / `versionCode` | 必须**严格大于**本机版本 | 拒绝（防降级/重放，见第五节） |
| `minHost` | 本机宿主版本必须 ≥ 它 | 不适用增量，退回整包 |
| `base` | 必须包含本机当前版本 | 不适用增量（跨版本跳跃），退回整包 |
| `expiresAt` | 必须晚于当前时间 | 拒绝（旧清单被重放时迟早过期） |
| `files[].path` | 相对路径、无 `..`、无盘符、扩展名白名单 | 拒绝（防路径穿越写到系统目录） |
| `files[].sha256` | 下载后逐个比对 | 拒绝该文件，整份补丁作废 |

### 3.3 签名密钥

- 私钥：`KidsSafeDesktop/Keys/update-signing-private.pem`（**已被 `.gitignore` 忽略**，
  不在仓库里，不入任何安装包；丢了就没法再发增量，只能整包——请离线备份两份）。
- 公钥：以常量形式写死在 `KidsSafeShared/Updates/UpdateVerifier.cs` 里。
  换密钥＝换公钥＝必须整包发一次。
- 算法：RSA-4096 + PSS + SHA-256（.NET 与 OpenSSL 都原生支持，不引第三方库）。
- 发版机上的签名脚本：`Scripts/build-patch.ps1`（第六节）。

## 四、Windows：下载 → 暂存 → 重启落盘

### 4.1 目录布局

```
%LOCALAPPDATA%\Programs\KidsSafeDesktop\      ← 安装目录（apphost、运行时、dll、Assets）
    KidsSafeDesktop.exe
    KidsSafeUpdater.exe                       ← 落盘器（随安装包一起装，单独的小程序）
    KidsSafeShared.dll
    Assets\...

%LOCALAPPDATA%\KidsSafeDesktop\updates\       ← 补丁工作区（与安装目录分开，卸载时可整体删）
    1.21\
        payload\KidsSafeShared.dll            ← 下载好的文件，保持相对路径
        plan.json                             ← 落盘计划（文件、哈希、要删的）
        backup\KidsSafeShared.dll             ← 落盘前的原件（回滚用）
        result.json                           ← 落盘结果（成功/失败/原因）
        ready.flag                            ← 只有这个文件存在才允许落盘
```

工作区放在 `%LOCALAPPDATA%\KidsSafeDesktop` 而不是安装目录，有两个好处：
安装目录保持干净（用户去点 exe 还是原来的），以及落盘失败时不会把半成品留在程序目录里。

### 4.2 时序

```
主程序（孩子正在用）
  │ ① GET /api/app/patch?platform=windows&from=1.20&code=21
  │ ② 验签 → 解析 → 比对本地哈希 → 只下不一样的文件 → 逐个验 SHA-256
  │ ③ 写 plan.json + ready.flag；家长面板显示「更新已就绪，重启后生效」
  │ ④ 退出时（或家长点「立即重启更新」）：起 KidsSafeUpdater --apply ... --pid <自己>
  ▼
KidsSafeUpdater.exe（无窗口、独立进程）
  │ ⑤ 等主程序退出（最多 60 秒，超时则放弃并写 result.json）
  │ ⑥ 再验一遍 payload 的 SHA-256（防止下载后被改）
  │ ⑦ 备份原件到 backup\ → 复制新文件 → 处理 removed 列表
  │ ⑧ 写 result.json，删 ready.flag
  │ ⑨ 重新拉起 KidsSafeDesktop.exe
  ▼
主程序启动
  └ ⑩ 读 result.json → 家长面板显示「已更新到 1.21」或「更新失败，已回滚」
```

关键点：

- **落盘一定在独立进程里做**。主程序自己是 `KidsSafeShared.dll` 的使用者，
  在进程内替换正在使用的 dll，Windows 会直接拒绝（共享冲突）；
  就算能改名，也解决不了「已经加载的旧代码继续跑」的问题。
- **失败要能退回去**。⑦ 里任何一步失败 → 把 `backup\` 里的文件搬回去、删掉新加的文件
  → 写 `result.json{ok:false}` → 仍然把旧版本拉起来。孩子的机器绝不能因为更新变成一块砖。
- **更新只在「关闭再打开」时生效**，不打断正在玩的孩子。这是刻意的产品选择：
  kiosk 应用弹一个「立即重启」对 5 岁小孩没有意义。

### 4.3 权限

安装器是 `PrivilegesRequired=lowest` + `DefaultDirName={localappdata}\Programs\...`，
所以安装目录本来就属于当前用户，落盘**不需要管理员权限**。
如果家长手工改到 `C:\Program Files`，落盘会失败——`KidsSafeUpdater` 检测到
目标目录不可写时，`result.json` 里写「安装目录需要管理员权限，请整包更新」，
不去弹 UAC（kiosk 会话里弹 UAC 是死路）。

## 五、Android：预加载覆盖（能到哪一步，说清楚）

### 5.1 硬约束

APK 是签名的只读包，`assemblies/`（或 Release 下的 `lib/<abi>/libmonodroid_bundle_app.so`）
里的程序集**无法在运行时替换**。原生 `.so`、`AndroidManifest.xml`、权限、图标同理。
所以「安卓也改成只更新 dll」这件事，只有一条路：**让运行时的程序集解析去用外部文件**。

### 5.2 做法：在任何业务代码之前预加载

.NET 的默认 `AssemblyLoadContext` 按**简单程序集名**缓存已加载的程序集。
如果我们在它第一次解析 `KidsSafeShared` 之前，先 `LoadFromAssemblyPath()`
把外部文件装进默认上下文，那么后续所有 `KidsSafeShared.*` 的类型引用都会绑定到这份新的。

```
Android 冷启动
  │ Main / MauiProgram.CreateMauiApp 的第一行
  ├─ PatchBootstrapper.Run()
  │    ├─ 读 files/patches/active.json（{版本, 文件列表}）
  │    ├─ attempts += 1 先落盘（防止「一加载就崩」导致无限崩溃循环）
  │    ├─ 逐个 Assembly.LoadFromAssemblyPath(files/patches/<版本>/X.dll)
  │    │    └ 任何一个抛异常 → 立即停用这份补丁（改名为 .broken）→ 继续用 APK 里的旧版
  │    └─ 成功 → 交给正常流程
  └─ 后面才是 AppLog.Install() / builder.Build() / 页面
```

- 顺序是**唯一**的硬要求：在 `PatchBootstrapper.Run()` 之前不能触碰任何
  `KidsSafeShared` 里的类型（包括 `Helpers.AppLog`）。所以它必须是
  `CreateMauiApp()` 的第一条语句，且自身只依赖 `System.*`。
- 「尝试计数」是防砖保险：连续两次启动都死在加载后，第三次自动停用补丁并清掉
  `active.json`，回到 APK 自带版本，同时在日志里留一条 `patch disabled`。
- 兼容性靠清单里的 `minHost` 兜住：补丁的 dll 必须与宿主（APK 里那份
  `KidsSafeDesktop.dll` + `Microsoft.Maui.*`）ABI 兼容。**只要壳工程的公开签名没变，
  换 `KidsSafeShared.dll` 是安全的；一旦改了 DI 注册的接口签名或 `App` 的构造函数，
  就必须整包。** 这条写进发版检查单，不靠记忆。

### 5.3 Android 的整包兜底

原生代码、清单、权限变了 → 只能整包。客户端已有 `/api/app/update-check`，
补齐「下载 APK → 用 `FileProvider` 拉起系统安装器」这一步即可
（sideload 应用没有 Play 的 in-app update，只能走系统安装器，会弹一次「是否安装」）。
这部分**不在本次改动范围内**，方案里标为下一步。

## 六、服务端与发版

### 6.1 接口

```
GET /api/app/patch?platform=windows&from=1.20&code=21
```

```json
{
  "ok": true,
  "available": true,
  "manifest": "<manifest.json 原始字节的 base64>",
  "signature": "<manifest.sig 的 base64>",
  "baseUrl": "/patches/windows/current/files/"
}
```

- 用 base64 包一层，是为了让客户端拿到的**字节与签名时完全一致**（见 3.1）。
- 文件本身走静态路由 `/patches/<platform>/current/files/<相对路径>`，由 Kestrel 直接发，
  不经过任何业务代码——省 CPU，也能直接丢到 Nginx / 对象存储后面。
- 服务端只做「读文件 + 判断 platform 是否匹配」，**不持有私钥、不在线签名**：
  签名发生在发版机上，服务端被攻破也发不出能通过验签的补丁。

### 6.2 发版机上的一条命令

```powershell
# 用上一版发布目录和这一版发布目录做 diff，生成补丁并签名
.\Scripts\build-patch.ps1 -Platform windows `
    -OldDir ..\_release\v1.20\win `
    -NewDir bin\Release\net10.0-windows10.0.19041.0\win-x64\publish `
    -Version 1.21 -VersionCode 22 -Base 1.20 -MinHost 1.20 `
    -OutDir ..\KidsSafeServer\wwwroot\patches\windows\current

# Android：同一份源目录结构，只挑 *.dll + 内容 JSON
.\Scripts\build-patch.ps1 -Platform android -OldDir ... -NewDir ... -Version 1.21 -VersionCode 22
```

脚本做的事：按相对路径比对两边文件 → 只复制「新增或 SHA-256 不同」的 →
生成 `manifest.json` → 用私钥签 `manifest.sig` → 打印体积对比
（「整包 108 MB → 增量 2.4 MB」）。**它不替你改版本号**，版本号仍由 `release.bat` 统一改。

## 七、安全边界（这一节比代码重要）

这是一个**家长控制**软件，自更新通道如果可被利用，等于给了一条绕过家长密码的后门。
所以：

| 威胁 | 处置 |
| --- | --- |
| 有人架一个假服务器，推一个「解锁全部」的 dll | 清单必须用私钥签名；公钥写死在客户端。假服务器发不出合法签名 |
| 用旧版（有漏洞）清单重放 | `versionCode` 必须大于本机 + `expiresAt` 过期即拒 |
| 清单里写 `..\..\Windows\System32\xx.dll` | 路径规范化后必须仍在安装目录内，且不含 `..`、不是绝对路径 |
| 塞一个 `KidsSafeDesktop.exe` 覆盖宿主 | 扩展名白名单只允许 `*.dll` 与内容文件，`*.exe` 直接拒绝整份清单 |
| 家里网络是明文 HTTP（自建服务器常见） | 签名不依赖 TLS，明文也不会被篡改后仍通过验签；只是内容可见（都是不敏感的程序文件） |
| 服务端被入侵 | 服务端没有私钥，改不了补丁内容；最多让客户端「更新失败」，不影响使用 |

**私钥保管**：`Keys/update-signing-private.pem` 只放在发版机 + 离线备份。
一旦怀疑泄露，立刻换一对密钥、把新公钥打进整包里发一次，之后旧私钥签的补丁全部失效。

## 八、与现有「整包更新」的关系

| 场景 | 走哪条路 | 客户端表现 |
| --- | --- | --- |
| 只改了 C# / XAML / 文案 / 图片 | **增量**（本方案） | 「更新已就绪，下次打开生效」，几 MB |
| 改了壳工程公开接口、DI 签名、`App` 构造 | 整包（`minHost` 拦下来） | 「需要完整更新」，走官网下载 |
| 改了 Android 原生库 / 清单 / 权限 | 整包 | 同上 |
| 服务端没配 / 断网 | 不检查 | 完全静默，不影响使用 |
| 补丁验签失败 / 下载失败 | 放弃这次，下次再试 | 家长面板显示一行原因，不弹窗 |

### 日常操作

```powershell
# 改完服务端代码，一条命令重新上线（发布 → 打包 → 上传 → 重启 → 公网验证）
.\deploy-server.bat
.\deploy-server.bat -SkipPublish     # 只重传上次的包

# 发一版增量补丁：先生成，再同步到服务器的 patches 目录
.\build-patch.bat windows -OldDir ..\_release\v1.20\win `
    -NewDir ..\_release\v1.21\win -Version 1.21 -VersionCode 22 -Base 1.20
scp -i C:/Users/Administrator/.ssh/id_rsa_49 -r `
    ..\KidsSafeServer\wwwroot\patches\windows\current `
    root@43.153.192.19:/opt/kidssafe-server/app/wwwroot/patches/windows/

# 确认客户端能看到的版本（null = 还没发补丁）
curl http://43.153.192.19/api/health
```

### 以后挂域名

客户端只认「家长服务器地址」这一个字段，所以换域名是**服务端的事，发一次整包都不需要**：

1. 在域名 vhost（例如新建 `api.siguangblog.cc.conf`）里复制 `location /api/`、`location /patches/`；
2. 解析 `api.siguangblog.cc` → `43.153.192.19`，证书用宝塔一键申请；
3. 客户端把服务器地址改成 `https://api.siguangblog.cc`（签名不依赖 TLS，但 HTTPS 更稳）。

### 首次注册

服务端是全新的 `data/`，`accountCount = 0`。家长第一次打开 `http://43.153.192.19/`
会看到注册页（`wwwroot/index.html` → `login.html`），**第一个注册的账号就是管理员**。
客户端要收到增量更新，家长面板里必须填了这个地址并保存（`ServerEnabled = true` 且 `ServerUrl` 非空），
否则更新检查会安静地跳过——这是刻意的：没连服务器就不该偷偷联网下载代码。
