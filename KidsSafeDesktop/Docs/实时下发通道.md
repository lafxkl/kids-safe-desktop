# 实时下发通道（长轮询）· 设计与验证

> 目的：家长在电脑上改完配置，孩子的手机/平板 **1 秒内**生效，不再需要点「立即同步」。
> 不依赖荣耀/华为等厂商推送（个人开发者拿不到企业资质），也不需要 WebSocket 中间件。

## 一、为什么是长轮询

| 方案 | 结论 |
|---|---|
| 荣耀 Push Kit | 个人开发者拿不到推送权限（需企业认证），当前一直 10202，已放弃 |
| WebSocket | 需要服务端支持（当前家长端是 ASP.NET 最小 API，加 WS 要引中间件 + 处理重连） |
| MQTT | 要额外部署 Broker，家用场景太重 |
| **长轮询** | 只要一个 GET 接口；穿透 NAT、断网重连都简单；儿童桌面常驻前台，耗电可忽略 |

## 二、服务端（KidsSafeServer）

新增文件 `WatchSignal.cs`，`Program.cs` 增加一个接口：

```
GET /api/watch?token=<家长令牌>&since=<客户端已知版本号>
```

- 版本号以**进程启动时刻的毫秒时间戳**为基准，每次 `PUT/POST /api/settings` 成功保存就 `Pulse(账号)` 一次，该账号版本 +1 并唤醒**属于这个账号**的挂起请求；
  - 为什么不用 0 起算：服务端一重启就从 0 重新计数，而客户端记得的是重启前的大数字，看起来像「版本倒退」，会被当成一次变更而多拉一次配置。用时间戳基准可保证重启后版本号只增不减。
  - 服务端 1.3 起版本号**按账号分桶**（`Dictionary<账号, Bucket>`）：同一台服务器上 A 家保存配置不会唤醒 B 家的设备。`/api/health` 里的 `watchVersion` 仍是所有账号的累计次数。
- 请求到达时若版本已变 → 立即返回 `{ok:true, version:n, changed:true}`；
- 若没变 → 挂起最多 **25 秒**，超时返回 `changed:false`，客户端立刻再发一次；
- 令牌无效返回 401，客户端提示「令牌失效」。

响应示例（版本号是时间戳量级，不是从 1 开始的小整数）：

```json
{ "ok": true, "version": 1793801901281, "changed": true }
```

## 三、客户端（KidsSafeDesktop）

`Services/LiveSyncService.cs`，注册为单例，在启动页「连接家长服务器」这一步启动：

1. 循环 `GET /api/watch`，带上上次的版本号；
2. 收到 `changed=true` → 调用已有的 `ServerSyncService.PullAsync()` 拉取配置并应用（主题、时长、应用白名单等）；
3. 成功应用后触发 `ConfigUpdated` 事件，家长面板收到后刷新界面并提示「家长端的配置已更新并生效」；
4. 失败按 2s → 4s → 8s → … → 30s 指数退避重连，**只改状态文字，不弹窗、不影响孩子使用**。

状态文字会显示在家长面板「家长端服务器」卡片下方，以及诊断页的「实时下发通道」一栏。

## 四、怎么验证

1. 电脑上运行 `KidsSafeServer`（默认 `http://0.0.0.0:5180`）；
2. 手机家长面板填地址 `http://<电脑IP>:5180` → 输入密码 1234 → 点「登录」；
3. 面板下方出现「实时通道：已连接」；
4. 在电脑浏览器打开 `http://localhost:5180`，改一项配置并保存；
5. 手机端 **1 秒内**应看到「☁️ 家长端的配置已更新并生效」，且时长/游戏开关同步变化。

诊断页同时会显示「循环运行：是 / 服务器地址 / 已登录」，排障时先看这三行。
