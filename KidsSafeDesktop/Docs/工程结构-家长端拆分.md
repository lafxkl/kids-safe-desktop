# 工程结构：孩子端 / 共享库 / 家长端

> 2026-11-12 拆分。原先孩子端与家长端在同一个 MAUI 工程里，家长中心只靠 PIN 门挡着。
> 现在拆成三个工程，**代码只有一份**，两个 App 只是不同的外壳与入口。

## 三个工程

| 工程 | 路径 | 作用 | 目标框架 |
|---|---|---|---|
| `KidsSafeShared` | `D:\WorkBuddy\KidsSafeShared` | 共享库：Pages / ViewModels / Services / Models / Helpers / Controls / Converters 全部在这里 | `net10.0-android` + `net10.0-windows10.0.19041.0` |
| `KidsSafeDesktop` | `D:\WorkBuddy\KidsSafeDesktop` | **孩子端**：儿童桌面。保留 PIN 保护的「家长」入口 | 同上 |
| `KidsSafeParent` | `D:\WorkBuddy\KidsSafeParent` | **家长端**：独立 App，启动直接进家长中心 | 同上 |

## 各自留了什么

**共享库**（绝大部分代码）
- `Pages/` 183 个页面文件
- `ViewModels/`、`Services/`、`Models/`、`Helpers/`、`Controls/`、`Converters/`
- `ServiceProvider.cs`（DI 静态入口）
- `Platforms/Android|iOS|Windows/` 里的三个 `NativeEyeCare` 与 `WindowsKioskService`（**带 `#if` 平台守卫**）

**孩子端**
- `App.xaml(.cs)`、`MauiProgram.cs`、`Platforms/`（MainActivity 541 行、荣耀推送、AAR、Kiosk 恢复）
- `Resources/`（图片、Raw 网页、字体、图标、启动图）

**家长端**
- 自己的 `App.xaml(.cs)`、`MauiProgram.cs`
- `Platforms/Android`：一个 20 行的普通 `MainActivity`（不接管系统键、不注册推送）
- `Platforms/Windows`：普通 WinUI 入口（**不**隐藏任务栏、不进 Kiosk）
- 复制的 `Resources/Styles`（配色/样式）、`Fonts`、`AppIcon`、`Splash`

## 关键约定（改代码前必读）

1. **命名空间保持不变**：共享库里的类仍是 `KidsSafeDesktop.*`，不是 `KidsSafeShared.*`。
   这是刻意的——341 个文件迁移过来一行 `using` 都没改。新增代码沿用 `KidsSafeDesktop.*`。
2. **两边都注册同一批转换器**：`InverseBool`、`AlertBg`、`HasPrecip`、`BoolToColor`、`HasItem`。
   共享页面里的 `{StaticResource InverseBool}` 是按 App 级资源查找的，某个 App 漏注册就会运行期崩。
3. **平台服务各自注册**：孩子端用真实的 `Platforms.Android/Windows.*`，家长端注册 `Stub*` 空实现
   （不枚举已装应用、不启动外部应用、不锁屏、不放音效、不打喜马拉雅）。
4. **共享库的 XAML 不能被 WindowsAppSDK 当 WinUI 页面编译**：csproj 里的
   `EnableDefaultPageItems=false` / `EnableDefaultApplicationDefinition=false` 不能删，
   删了会得到 `XamlCompiler.exe 退出码 1`、且没有任何具体报错。

## 构建

```bash
# 孩子端
dotnet build D:/WorkBuddy/KidsSafeDesktop/KidsSafeDesktop.csproj -f net10.0-windows10.0.19041.0 -c Debug

# 家长端
dotnet build D:/WorkBuddy/KidsSafeParent/KidsSafeParent.csproj -f net10.0-windows10.0.19041.0 -c Debug
```

> 不要在 `D:\WorkBuddy` 根目录直接 `dotnet build`：`KidsSafeDesktop.slnx` 里包含
> `KidsSafeServer`（只声明 net10.0），会报 `NETSDK1005`。

## 还没做的

- **没有真机验证**：孩子端/家长端在 Windows 上都实际启动过（无异常），
  Android 只验证了能编译出包，没装机跑过。
- **家长端的图标/名称是临时借用孩子端的**（`Resources/AppIcon` 拷了一份），
  应用名暂定「家长端」，`ApplicationId` 为 `com.companyname.kidssafeparent`。
- **跨设备数据不共享**：两个 App 各自读写本机 `Preferences`/JSON。
  要让家长在自己手机上改配置、孩子设备生效，必须走已有的 `KidsSafeServer` + `LiveSyncService`
  （孩子端本来就有长轮询通道）。这块没动。
- **家长端没有独立安装包/发布脚本**：`release.bat`、`Installer/` 仍只服务孩子端。
- **家长端 APK 里仍带着孩子端的权限声明**（`AndroidManifest.xml` 是从孩子端复制的，
  含查询已装应用、悬浮窗等）。上架前应按需裁剪。

## 补充：安卓侧的钩子（AndroidHooks）

安卓平台服务（`AndroidKioskService`、`AndroidAppLauncherService`、`VoiceInput`、`HonorPush` 等）
也搬进了共享库，但它们原本直接调用 App 自己的 `MainActivity`。共享库不能反向依赖 App，于是加了一个窄钩子：

```csharp
// KidsSafeShared/Platforms/Android/AndroidHooks.cs
public static Action? ApplyLockTaskNow { get; set; }
public static Action? ApplyImmersiveNow { get; set; }
public static Action? AllowExit { get; set; }
public static Action<TimeSpan>? SuppressAutoReturnFor { get; set; }
public static Type? MainActivityType { get; set; }
```

孩子端的 `MainActivity.OnCreate` 里把五个方法挂上去；家长端不注册，调用即空操作（不会崩）。
**以后新增「必须由 Activity 执行」的能力，走这个钩子，不要在共享库里引用 MainActivity。**
