# 用户反馈 · 满意度 · 问卷（四端 + 官网）

> 一句话：家长在任一端口说的一句话，几秒后就会出现在官网的公开统计里；开发者用管理密钥能看明细、导 CSV、按用户要求删除。
>
> 数据链路只有一条：`客户端 → https://kids.siguangblog.cc/api/feedback/submit → 服务端 data/feedback/*.jsonl → 官网 /feedback.html、/comments.html 与 /feedback-admin.html`。

---

## 一、产品上有什么

三类提交，共用一套字段与一个接口。入口都在**家长面板**（反馈是给家长说的，不给孩子）：

| 类型 | `kind` | 必填 | 选填 | 用途 |
|---|---|---|---|---|
| 意见反馈 | `feedback` | 分类 + 正文（≥5 字） | 联系方式、是否匿名展示 | 报 bug、提功能、纠错 |
| 满意度调查 | `satisfaction` | 整体满意度 1–5 星 | 5 个分项、NPS 0–10、喜欢的功能、建议、联系方式、匿名展示 | 判断「这一版到底好不好用」 |
| 使用问卷 | `survey` | 6 道单选里至少 3 道 | 补充说明、联系方式、匿名展示 | 决定下一版先做什么 |

设计上的几个刻意选择：

- **不填身份也能说完**：没有昵称、没有账号、没有手机号验证。联系方式是纯选填。
- **默认不公开**：「允许匿名展示在官网」默认关闭。不勾选，这条内容永远不会出现在公开页面上。
- **满意度只有整体分必填**：分项、NPS 都可以跳过。强迫全部填完，换来的是一堆随便点的 4 分。
- **问卷至少 3 题**：低于 3 题的样本没法判断，宁可不收。

## 二、接口契约（KidsSafeServer 1.4）

所有接口都在官网同域下（nginx 反代 `/api/` 到容器），没有跨域问题。

### `POST /api/feedback/submit`

```json
{
  "id": "客户端生成的 uuid",
  "kind": "feedback | satisfaction | survey",
  "platform": "windows | android | linux | harmony | web",
  "appVersion": "1.20",
  "channel": "parent-dashboard",
  "contact": "选填",
  "rating": 4,
  "nps": 8,
  "dims": { "ease": 5, "content": 4, "stable": 3, "design": 5, "value": 4 },
  "tags": ["护眼提醒", "小游戏"],
  "answers": { "孩子年龄": "6–8 岁" },
  "content": "正文，最多 2000 字",
  "public": false
}
```

返回 `{ "ok": true, "duplicate": false, "id": "..." }`。

- **幂等**：同一个 `id` 重发只会记一条（`duplicate: true`）。断网重试、用户连点都不会把数据弄脏。
- **校验**：`kind` 白名单；正文 2000 字封顶；联系方式 120 字；标签最多 12 个；问卷最多 40 题、每题 500 字；控制字符会被清掉。
- **「什么都没写」不算数据**：正文、评分、问卷作答全空的提交直接 400。
- **限流**：同一 IP 10 分钟 12 条、24 小时 60 条（429）。nginx 反代后优先看 `X-Forwarded-For`，否则会退化成全站共享额度。

### `GET /api/feedback/stats?days=30`

公开。给官网看板用，**不含任何联系方式**：

```json
{
  "total": 42, "today": 3, "last7": 11,
  "byKind": { "feedback": 10, "satisfaction": 24, "survey": 8 },
  "satisfaction": { "count": 24, "avgRating": 4.6, "dist": [0,0,1,8,15],
                    "nps": 62, "dims": { "ease": { "count": 20, "avg": 4.5 } } },
  "tags": [ { "tag": "故事屋", "count": 9 } ],
  "withContact": 3, "withContent": 30
}
```

`days=0` 表示全部时间。NPS 按标准口径算：9–10 为推荐者、0–6 为贬损者。

### `GET /api/feedback/quotes?limit=6`

公开。只返回**勾选了「允许匿名展示」**的留言，字段只有 `kind / rating / content / nickname / month / platform` —— 连具体日期都不给，避免「某天某条」被对上号。

`limit` 上限 100（1.4.1 起，官网评论区要整页展示）；`nickname` 是用户自己填的展示名，没填就是 `null`，前端显示「匿名家长」——不是从设备或账号推断的。

### 管理端（需要密钥）

| 接口 | 说明 |
|---|---|
| `GET /api/feedback/list?key=…&kind=&days=&limit=&offset=` | 明细（含联系方式） |
| `GET /api/feedback/export.csv?key=…` | 导出，带 UTF-8 BOM，Excel 双击不乱码 |
| `DELETE /api/feedback/{id}?key=…` | 删除（按用户要求），会重写当月 JSONL |

密钥来源两选一：

1. `appsettings.json` 的 `Feedback:AdminKey`（推荐，官网管理页用这个）；
2. 已登录的 `owner` 账号令牌（开发机上不改配置也能看）。

比较走定长比较，避免按响应时间逐字节猜密钥。没配 `AdminKey` 时启动日志会明确提示。

## 三、数据落在哪

```
KidsSafeServer/data/feedback/
├─ 2026-11.jsonl     一行一条，UTF-8 无 BOM（grep / tail -f 直接看中文）
└─ 2026-12.jsonl
```

为什么不用数据库：这层数据量是「每月几十到几百条」，SQLite 的备份、锁、迁移成本大于收益；JSONL 可以直接 `grep`、直接拷走、出问题用记事本就能看。真到几万条再换，接口形状不用变。

- 启动时把全部记录读进内存（去重集合 + 列表），追加时同步维护；
- 单行坏掉不影响其它行（手工编辑、写一半断电都可能出现半行）；
- 删除采用「写 `.tmp` → `File.Move` 覆盖」，重写中途断电不会留下半个文件。

**备份**：`docker cp kidssafe-server:/app/data/feedback ./backup-$(date +%F)` 即可；恢复反向拷回。

## 四、四端实现位置

| 端 | 服务 | 页面 | 入口 |
|---|---|---|---|
| Windows / Android | `KidsSafeShared/Services/FeedbackService.cs` | `Pages/FeedbackPage.xaml`、`SatisfactionPage.xaml`、`SurveyPage.xaml` | 家长面板「💬 意见反馈与问卷」卡片 |
| Linux | `Linux/src/core/feedback.{h,cpp}` | `Linux/src/qml/FeedbackPage.qml` | 家长页「意见反馈与问卷」卡片 |
| 鸿蒙 | `Harmony/.../core/Feedback.ets` | `Harmony/.../pages/FeedbackPage.ets` | 家长页 `feedbackCard` |

四端都遵守同样的三条：

1. **地址固定官网**（`https://kids.siguangblog.cc`），不跟家长自建的服务器走。反馈是给开发者的，指向家长自己的机器等于没发。
   - 联调覆盖：Windows/Android 用偏好项 `feedback.base_url`；Linux 用环境变量 `KIDSSAFE_FEEDBACK_URL`；鸿蒙改 `core/Feedback.ets` 里的 `BASE_URL`。
2. **只带平台与版本号**，不带设备标识、昵称、账号。
3. **断网不丢**：先入本机队列，联网后自动补传。

### 离线队列

| 端 | 位置 | 触发补传 |
|---|---|---|
| Windows / Android | `AppDataDirectory/feedback_queue.json` | 进家长面板时、进任一反馈页时、下次提交时 |
| Linux | `~/.local/share/kidssafe/feedback_queue.json` | 启动 3 秒后、进页面时、下次提交时 |
| 鸿蒙 | preferences 的 `feedback_queue` 键 | 进页面时、下次提交时 |

队列上限：Windows/Android 不设硬上限（一份正文最多 2 KB，攒不出问题）；三端都只保留最近的记录，发送成功即删除。4xx（内容不合格）会直接丢弃并显示原因——同一条坏数据重试一万次也不会成功。

## 五、官网三个页面

### `/feedback.html` —— 公开的提交页

- 三个标签：满意度调查 / 使用问卷 / 意见反馈；
- 右侧实时统计：收到份数、平均满意度、NPS、分项条形、标签云、匿名留言；
- 断网时把内容存 `localStorage`，下次打开自动补传；
- 内容不会当 HTML 插入（`textContent`），用户输入里带 `<script>` 也只是文字。

### `/feedback-admin.html` —— 明细与导出

- 密钥只放 `sessionStorage`，关标签页即失效；请求头 `X-Admin-Key` 传递，不写进 URL、不进浏览器历史、不进 nginx 访问日志；
- 支持按类型/时间筛选、分页、展开看分项与问卷作答、单条删除、导出 CSV。

### `/comments.html` —— 公开的评论区

两路数据合并，按正文去重：

1. `Website/data/comments.json`：静态精选，运营直接改文件就能更新（下面的「数据怎么维护」）；
2. `GET /api/feedback/quotes?limit=100`：用户在 App 或官网刚提交、且勾选了公开的留言。

页面能力：

- 按平台（Windows / Android / Linux / 鸿蒙 / 官网）与星级筛选，按最新 / 最有用 / 评分排序，每页 9 条「加载更多」；
- 点赞只写本机 `localStorage`，**不发给服务端**——没有账号体系，防不住刷，与其做个假数字不如老实承认；
- 页面底部直接发表，走同一套 `POST /api/feedback/submit`（`channel=website-comments`，`platform=web`），带昵称；断网时进 `localStorage` 队列，下次打开自动补传；
- 发表成功后先在本页插一条「刚刚提交」的卡片，不用刷新就能看到自己写的；
- 首页 `index.html` 的「家长怎么说」读同一份 JSON 取 6 条（`featured` 优先），拉不到就整块隐藏——不留空框，也不写死假评价。

三页都已加入 `Scripts/deploy.ps1` 的 `$CoreFiles`；`feedback.html` 与 `comments.html` 进 `sitemap.xml`（管理页刻意不进，并带 `noindex`）。

### 评论区数据怎么维护（`Website/data/comments.json`）

纯静态 JSON，改完保存、刷新页面即生效，不用重新构建，也不用动 HTML。

```json
{
  "version": 1,
  "updatedAt": "2026-11-24",
  "items": [
    {
      "id": "c-20261124-01",
      "name": "浩浩妈妈",
      "avatar": "浩",
      "platform": "windows",
      "rating": 5,
      "date": "2026-11-24",
      "tags": ["护眼提醒", "时长限制"],
      "content": "……",
      "likes": 41,
      "featured": true,
      "reply": { "date": "2026-11-24", "content": "……" }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一即可，重复会导致点赞状态串台 |
| `platform` | `windows` / `android` / `linux` / `harmony` / `web`，其它值不显示徽章 |
| `rating` | `0` 或 `1–5`；`0` 表示不打分，只显示正文 |
| `date` | `YYYY-MM-DD`，评论区按它倒序 |
| `avatar` | 一个字符（首字最好看）；不填取 `name` 第一个字 |
| `likes` | 展示用初始值；用户点的赞只存在他自己浏览器 |
| `featured` | `true` 才会出现在首页「家长怎么说」 |
| `reply` | 选填，开发者回复，会显示在卡片下方 |

**部署时的覆盖保护**：`deploy.ps1` 会把 `data/` 一起传上去，但传之前先比远端与本地 mtime——线上那份更新就跳过并提示，确认要以本地为准加 `-ForceData`。所以「直接在服务器上改 JSON」和「改仓库再部署」两种做法都不会互相打架。

## 六、运维：上线要做的三件事

1. **nginx 留出 `/api/` 与 `/patches/` 反代**（`kids.siguangblog.cc` 已配好，换服务器时照抄）：

   ```nginx
   location ^~ /api/ {
       proxy_pass http://127.0.0.1:5180;
       proxy_http_version 1.1;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       # 这一行不能省：不传的话服务端只看到 127.0.0.1，限流会变成「全站共用 12 条/10 分钟」
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_read_timeout 60s;
   }
   ```

   用 `^~` 而不是普通前缀：正则 `location` 优先级更高，以后加规则容易把 `/api/` 抢走。

2. **配管理密钥**（服务器 `/opt/kidssafe-server/app/appsettings.json`）：

   ```json
   "Feedback": { "AdminKey": "换成一串足够长的随机字符" }
   ```

   改了要 `docker restart kidssafe-server`。密钥不要提交进仓库；重新部署时用
   `deploy-server.ps1 -AdminKey …` 通过环境变量覆盖也行。

3. **部署服务端 → 部署官网**：`deploy-server.bat`，然后 `deploy.bat`。

> 顺序不能反：官网页面依赖 `/api/feedback/stats`，服务端没上时页面能打开，但统计区一直显示「还没有足够的数据」。
>
> `deploy-server.ps1` 打包时**排除 `appsettings.json`**：服务器那份才是真配置（Mxnzp 密钥、AdminPin、`Feedback:AdminKey` 都在里面），拿仓库版本覆盖会直接搞坏线上。这个坑 2026-11-24 实际踩过一次。

### 日常

- 看数据：`https://kids.siguangblog.cc/feedback-admin.html`；
- 导出：同页「导出 CSV」，或 `curl -H "X-Admin-Key: …" …/api/feedback/export.csv -o feedback.csv`；
- 删除某条：管理页点删除，或 `curl -X DELETE -H "X-Admin-Key: …" …/api/feedback/<id>`；
- 健康检查：`/api/health` 里的 `feedbackCount` 一行就是总条数；
- 改评论区展示：编辑 `Website/data/comments.json`（仓库改完 `deploy.bat`，或直接改服务器同名文件——部署脚本比 mtime，不会互相覆盖），详见第五章末。

## 七、隐私边界（与隐私政策 1.1 一致）

- **不存** IP、账号、设备标识、位置；接口里没有这些字段，也不写访问日志到数据文件。
- **联系方式**只有管理端能看到，公开统计接口永远不带。
- **公开**需要用户明确勾选，默认关闭；公开时只显示正文、星级、月份、平台。
- **保留** 24 个月用于版本对比；用户发邮件要求删除时，15 个工作日内处理（管理页删除是不可恢复的）。
- 应用内隐私政策版本已从 1.0 升到 1.1，老用户升级后会重新看到同意页——这是新增处理目的时应有的动作，不是打扰。

## 九、已知限制

- **鸿蒙端未在本机编译验证**：本机没有 DevEco Studio，`FeedbackPage.ets` / `Feedback.ets` 只做了静态核对（API 名称、组件约束）。第一次在 DevEco 里打开时，若报 `@Builder` 或 `Record` 相关错误，优先检查 ArkTS 严格模式下的对象字面量写法。
- **Linux 端未在本机编译验证**：没有 Qt 6 环境，`feedback.cpp` 走的是与 `storyservice.cpp` 相同的 `QNetworkAccessManager` 模式，风险较低但同样未实际链接。
- **限流按 IP**：同一出口 NAT 下的多个家庭会共享额度（12 条/10 分钟），正常使用碰不到；如果将来做活动拉问卷，需要调大或改成按 `id` 预热。
- **CSV 导出上限 5 万行**：够用很久；真到了这个量级应该直接读 JSONL 做离线分析。
- **公开统计没有缓存**：每次打开页面都会读一遍内存列表。条数上万后再考虑加 60 秒缓存。
