# 小游戏工坊（内置网页编辑器）

给家长用的「不写代码做小游戏」工具。四端（Windows、Android、Linux、鸿蒙）共用**同一份单文件 H5**，
各端只做宿主才做得到的事：把页面装进 WebView、调系统选图器、把作品存成文件。

## 一、为什么不给每端写一套编辑器

编辑器里有模板引擎、试玩循环、素材库、存档判断，全部是纯前端逻辑。四端各写一遍的结果是：
改一个判定规则要改四处，改漏一处就会出现「电脑上好用、手机上说不好玩」。

所以边界划在 WebView 上：

| 端 | 编辑器来源 | 宿主补的三件事 |
| --- | --- | --- |
| Windows / Android | `Resources/Raw/Maker/index.html`（MauiAsset，首次启动释放到 `AppData/maker`） | `FilePicker` 选图、`FilePicker` 读 `.json`、`Share` 导出 |
| Linux (Qt6) | `assets/maker/index.html`（装到 `share/kidssafe/maker`，直接 `file://` 打开） | `FileDialog` 选图/选文件、`QImage` 缩图、`QFile` 写导出 |
| 鸿蒙 | `resources/rawfile/maker/index.html`（`$rawfile`） | `PhotoViewPicker` 选图、`DocumentViewPicker` 读写 |

编辑器不要资源清单、不要路由、不要网络权限 —— 一句 `<WebView>` 装进去就能跑。

## 二、功能与边界

**内置三种玩法模板**（新建时选，之后每个参数都能改）：

| 模板 | 玩法 | 可调参数 |
| --- | --- | --- |
| 接住掉落 🧺 | 左右移动接住好东西，接到 `goal` 个过关 | 主角、掉落物、速度、时长、目标数、命数 |
| 躲开障碍 🏃 | 左右躲闪，别撞上掉下来的障碍 | 主角、加分物、障碍、速度、时长、目标分、命数 |
| 点一点 👆 | 目标随机出现，点到得分 | 目标、速度、时长、目标分、命数 |

**内置素材**：6 类 emoji（动物 16、水果 14、星星 12、交通 12、怪兽 10、自然 10）+ 8 套背景渐变。
全部是字符和 CSS 渐变，不占包体、不会加载失败。

**外部素材导入**：选一张本地图片 → 宿主读字节 → 缩到 480px（MAUI）/ 缩放后 base64（Qt）→
以 `data:` URL 喂给页面 → 页面再压到 320px 存进存档。单张上限 8 MB，超过劝退而不是硬塞
（10 MB 原图 base64 后 13 MB，安卓上过 JS 桥会卡死）。

**作品导出/导入**：一个 `.json`，含模板、参数、素材（图片是 data URL，所以文件自带全部素材，
换设备直接能打开）。

## 三、作品存在哪（这条最重要）

家长做的作品默认存在**页面的 localStorage**里。这意味着：**释放路径一变，等于把所有作品丢了**。

| 端 | 存储位置 | 注意 |
| --- | --- | --- |
| Windows / Android | WebView 站点数据（`file://` origin） | 释放目录固定为 `FileSystem.AppDataDirectory/maker`，`MakerAssets.Folder` 这个常量不能改名 |
| Linux | `~/.local/share/kidssafe/QtWebEngine/Default/Local Storage` | 装了 `qml6-module-qtwebengine` 才有；卸载时若清 `~/.local/share/kidssafe` 会一起没 |
| 鸿蒙 | `preferences`（经 `window.KSStore` 桥） | `resource://rawfile` 这个 origin 不保证给 opaquestorage，所以鸿蒙端必须走桥，不能只靠 localStorage |

鸿蒙端为什么特殊：`$rawfile` 加载的页面 origin 是 `resource://rawfile/`，实测「当场存得进去、重开就空」。
页面里的存储层做了适配 —— 有 `window.KSStore` 就优先用它，没有才退回 localStorage
（`index.html` 第 2 节，`KSStore.get/set`）。

## 四、页面给宿主留的接口

宿主只需要调这几个，全在 `window.KS` 上：

| 接口 | 用途 |
| --- | --- |
| `KS.importAsset({name, mime, dataUrl})` | 导入一张图片素材，返回 `'ok'` / `'full'` / `'bad-payload'` |
| `KS.loadProjectBase64(b64)` | 打开一个作品（UTF-8 字节的 base64），返回 `'ok'` |
| `KS.currentProjectBase64()` | 取当前作品的 base64，没打开作品返回 `''` |
| `KS.projectName()` | 当前作品名（导出时的默认文件名） |
| `KS.goLibrary()` | 回到作品大厅（鸿蒙返回键、安卓物理返回键用） |

**为什么要 base64 而不是直接给路径**：三个平台的 WebView 都不能可靠地读宿主的绝对路径
（安卓 `file://` 受限、鸿蒙 `rawfile` 与沙箱路径不同、Windows 有 MSIX 虚拟化）。字节过桥最笨但最稳。

## 五、改编辑器之后要做什么

编辑器是**同一份文件放在三个地方**，改完必须同步，否则四端行为会悄悄分叉：

```sh
cp Resources/Raw/Maker/index.html Linux/assets/maker/index.html
cp Resources/Raw/Maker/index.html Harmony/entry/src/main/resources/rawfile/maker/index.html
```

MAUI 端还有一道版本号：`KidsSafeShared/Helpers/MakerAssets.cs` 的 `Version` 常量。
页面靠它判断「要不要重新释放」——**改了 index.html 但没改版本号，老用户拿到的还是旧页面**。

## 六、排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 白屏，什么都没有 | 资源没进包 | Windows/安卓看 `Resources/Raw/Maker/index.html` 是否被 `MauiAsset` 收进去；Linux 看 `share/kidssafe/maker/index.html` 在不在；鸿蒙看 `rawfile/maker/index.html` |
| 作品「当时存住了，重开就没了」 | origin 没给 storage | Windows/安卓检查 `DomStorageEnabled`（代码里已设）；鸿蒙检查 `javaScriptProxy` 的 `methodList` 是否与 `KSStore` 方法名一致 |
| 点「导入素材」没反应 | Linux 缺 `qml6-module-qtquick-dialogs` | `sudo apt install qml6-module-qtquick-dialogs`，或直接拖图进页面（页面里也支持拖放） |
| 导入图片后卡一下 | 原图太大 | 上限 8 MB 是硬闸；正常手机照片经宿主缩图后只剩几十 KB |
| 导出的文件打不开 | 不是工坊产出的 json | `loadProjectBase64` 会校验 `schema`/`template` 字段，坏文件返回非 `ok` |
| 页面能开但点不动 | WebView 失去焦点 | Linux 已给 `focus: true`；安卓/Windows 点击即取焦点 |

## 七、刻意不做的事

- **不做任意 HTML/JS 编辑**：给家长一个能跑任意脚本的框，等于把儿童机的 kiosk 边界拆了。
  模板 + 参数 + 素材已经覆盖「做个能玩的小游戏」这个需求。
- **不让页面联网**：三端都拦了非本地 URL（Linux 无外链入口、MAUI `Navigating` 拦截、鸿蒙 `onLoadIntercept`）。
- **不做作品云同步**：作品里有家长自己拍的图，默认不出设备。要分享用导出的 `.json`。
