## 0. 先看这一条：线上现在没有 sitemap.xml

本地文件是有的：

```
D:\WorkBuddy\KidsSafeDesktop\Website\sitemap.xml   1,238 字节   5 条 <url>
```

**线上是 404。** 2026-11-05 23:42 实测：

| 地址 | 线上状态 | 说明 |
|---|---|---|
| `/` | 200 | 但 `Last-Modified: 05 Nov 11:15 GMT` = 本地 19:15 的旧版本 |
| `/robots.txt` | **404** | 本地已有 |
| `/sitemap.xml` | **404** | 本地已有 |
| `/about.html` | **404** | 本地已有 |
| `/favicon.ico` | **404** | 本地已有 |
| `/nope-abc` | 404 | 返回的是 nginx 默认页，不是 `404.html` |

结论一句话：**代码改完了，但还没传上去。** 这时候在 Bing 后台提交 sitemap 一定会失败——
Bing 会去抓 `https://kids.siguangblog.cc/sitemap.xml`，拿到的是 404。

**正确顺序永远是：部署 → 线上自检 → 再回 Bing 后台提交。** 顺序颠倒就会出现「我提交了但一直没收录」。

如果之前已经在 Bing 后台点过提交，不必撤回：部署完再点一次提交即可，Bing 每次提交都会重新抓。

## 1. 一次性配置（只做一次，做完打勾）

### 1.1 nginx：在**现有** server 块里加，不要整块替换

`ssl_certificate` / `ssl_certificate_key` 两行保持你原来的，不要动。只把下面这些插进去：

```nginx
server {
    listen 443 ssl;
    http2 on;                      # nginx ≥ 1.25.1 这样写；老版本改回 listen 443 ssl http2;
    server_name kids.siguangblog.cc;

    root /var/www/kids;            # ← 必须和 deploy.bat 的 remotePath 是同一个目录
    index index.html;

    charset utf-8;                 # 不加的话 .txt / .xml 里的中文可能乱码
    charset_types text/css application/javascript application/json application/xml text/plain;

    # ① / 与 /index.html 只留一个地址，避免重复内容
    location = /index.html {
        return 301 https://kids.siguangblog.cc/;
    }

    # ② 自定义 404（关键：没有这两行，404.html 永远不会出现）
    error_page 404 /404.html;
    location = /404.html { internal; }

    # ③ HTML 不缓存，图片与安装包长缓存
    location ~* \.html$ {
        add_header Cache-Control "no-cache";
    }
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public";
    }
    location /downloads/ {
        expires 7d;
        add_header Cache-Control "public";
        add_header Accept-Ranges bytes;   # 断点续传，大 APK 必须
    }

    # ④ 告诉浏览器这两个文件是什么类型（有的机器会把 .xml 当下载）
    location = /sitemap.xml { default_type application/xml; }
    location = /robots.txt  { default_type text/plain; }
    location ~ ^/[0-9a-f]{32}\.txt$ { default_type text/plain; }   # IndexNow 密钥
}
```

`http{}` 里确认开了压缩（如果已有就跳过）：

```nginx
gzip on;
gzip_min_length 1k;
gzip_comp_level 6;
gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;
```

生效与验证（**必须先 `-t`，语法错会直接把站点打挂**）：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

- [ ] `nginx -t` 通过
- [ ] `reload` 成功
- [ ] 五条自检命令全绿（见 3.1）

## 2. 三种日常场景，照抄命令

### A. 只改文案 / 加内链（不动版本号）

```powershell
.\deploy.bat -Server root@你的IP
```

十几秒。改完顺手在 Bing 后台对那个页点一次「URL 检查 → 请求编入索引」。

### B. 发新版（有新 APK / ZIP）

```powershell
.\release.bat 1.18 19                    # 先出包：改版本号、双平台编译、打 zip、回填网页
.\deploy.bat -Server root@你的IP -WithDownloads
```

`release.ps1` 第 11 步会自动回填：JSON-LD 的 `softwareVersion`、sitemap 三个页面的 `lastmod`、about 页的「N 个已发布版本」。
**发版后必做**：Bing 后台对首页与 changelog 请求编入索引（新版本号是抓取信号）。

### C. 新增一个页面

1. 写页面，`<head>` 里照现有页面补齐 5 件套：`title` / `description` / `canonical` / `og:*` / JSON-LD
2. 至少加 3 条内链指向它（页脚或相关页）
3. 在 `Website/sitemap.xml` 里加一条 `<url>`，`lastmod` 写今天
4. `deploy.bat -Server root@你的IP`
5. Bing 后台提交该 URL

**漏第 3 步 = 页面永远等不到爬虫。** 这是最常见的失误。

## 3. 巡检

### 3.1 每周 10 分钟（复制粘贴）

```bash
# ① 六个关键地址的状态
for u in / /about.html /sitemap.xml /robots.txt /favicon.ico /nope-abc; do
  printf "%-14s " "$u"; curl -s -o /dev/null -w "%{http_code}\n" "https://kids.siguangblog.cc$u"
done
# 期望：200 200 200 200 200 404

# ② 404 是不是自己的页面（不是 nginx 默认页）
curl -s https://kids.siguangblog.cc/nope-abc | grep -c "这个页面走丢了"      # 期望 1

# ③ sitemap 的 MIME 对不对
curl -sI https://kids.siguangblog.cc/sitemap.xml | grep -i content-type    # 期望 application/xml

# ④ /index.html 有没有 301 到 /
curl -sI https://kids.siguangblog.cc/index.html | grep -i "HTTP/\|location" # 期望 301

# ⑤ 有没有真开 HTTP/2
curl -sI --http2 https://kids.siguangblog.cc/ | head -1                     # 期望 HTTP/2

# ⑥ 证书还有多少天
echo | openssl s_client -connect kids.siguangblog.cc:443 2>/dev/null | openssl x509 -noout -dates

# ⑦ 服务器错误日志
sudo tail -n 100 /var/log/nginx/error.log | grep -v "SSL_do_handshake\|robots"
```

### 3.2 每周还要看的两块后台

| 看什么 | 在哪 | 判断标准 |
|---|---|---|
| 收录页数 | Bing 后台 → 站点资源管理器 | 5 页全收；两周还没动静就手工请求编入索引 |
| 搜索词 | Bing 后台 → 搜索性能 | 出现「儿童桌面」「儿童安全桌面」说明品牌词已立住；出现你没想到的词，就是下一个内容页的选题 |

补充一条最快的体感检查：在 Bing 搜 `site:kids.siguangblog.cc`，条数就是收录数。

### 3.2.1 微信群二维码（有有效期，必须定期换）

微信群二维码是**一次性、7 天有效**的，这是微信的机制，不是我们的实现问题。

| 什么时候 | 做什么 |
|---|---|
| 快到期前 | 微信「群二维码」重新生成，截图后裁掉上方群名与下方「该二维码 7 天内有效」文字，**只留二维码本体**，四周留白边（静区 ≥ 4 个模块宽，约 50 px） |
| 换图 | 覆盖 `Website/assets/wechat-group.png`，`index.html` 与 `about.html` 里 `width/height` 按新图实际尺寸改 |
| 改日期 | `index.html` 底部脚本里的 `deadline` 改成新码到期日；中间那张卡片 `.expire` 的文案日期同步改 |
| 部署 | `deploy.bat`（assets 会整个目录上传，不用加参数） |

漏了也不要紧：页面底部那段 JS 会在过期后自动把提示换成「本码已过期，请加 QQ 群索取」并标红，不会让家长对着失效码反复扫。
但**页面自己变红字只是兜底，别把它当成更新机制**——群里进不来人，损失的是真实用户。

> 长期做法：微信群够 200 人后，改成「加个人微信、拉进群」的固定码，就不用每 7 天换一次了。

### 3.2.2 三张二维码的资产清单（静态，一般不用动）

| 文件 | 是什么 | 尺寸 | 什么时候换 |
|---|---|---|---|
| `assets/qq-group.png` | QQ 群 1134839505 | 562×562 | 群号变了、群解散重建 |
| `assets/wechat-group.png` | 微信交流群（7 天码） | 847×847 | 见 3.2.1，到期就换 |
| `assets/wechat-mp.png` | 公众号「时光笔记」 | 490×490 | 公众号改名或换了新的关注码 |

三张都做成正方形、四周留够静区（≥ 4 个模块，约 50 px 白边），页面上由 CSS 等比缩小显示，所以原图越大越清晰；**不要拿小图拉伸放大**，模块边缘一糊就扫不出来。

公众号名字写了两处：`index.html` 的 `.chan h3`（「公众号：时光笔记」）和 `about.html` 的 `.qcard b`（「时光笔记」+「微信公众号」）。改名时两处一起改，`alt` 里的「公众号「时光笔记」二维码」也跟着改——这三处是搜索引擎和读屏软件唯一能读到的公众号信息。

## 4. 故障速查表

| 现象 | 最可能的原因 | 怎么确认 | 处置 |
|---|---|---|---|
| 传了但线上还是旧内容 | 传到别的目录了 / nginx `root` 指向别处 | `curl -sI https://…/ \| grep Last-Modified` 与本地文件修改时间对比；远端 `ls -l /var/www/kids` | 把 `deploy.config.json` 的 `remotePath` 改成 nginx 里那个 `root` |
| 浏览器看到旧版，别人看是新版 | HTML 被缓存 | 响应头有没有 `Cache-Control: no-cache` | 补 1.1 的第 ③ 条；用户侧 Ctrl+F5 |
| 404 还是 nginx 默认页 | 少了 `error_page 404` | `curl https://…/nope-abc \| grep nginx` | 补 1.1 的第 ② 条并 reload |
| Bing 提交 sitemap 报「无法获取」 | 线上 sitemap 是 404，或 XML 语法错 | `curl -sI …/sitemap.xml` 看状态；`xmllint --noout sitemap.xml` | 先部署；XML 报错就修标签闭合 |
| IndexNow 返回 403 | 密钥文件不可读 / 内容与文件名不符 | `curl https://…/da9d8752….txt` | 确认 `.txt` 在站点根目录、内容是 32 位 hex 且与文件名一致、`default_type` 设置正确 |
| 中文变乱码 | 缺 `charset utf-8` | `curl -sI …/robots.txt \| grep -i content-type` | 补 `charset` |
| 一直是 HTTP/1.1 | 没开 http2 | `curl -sI --http2 … \| head -1` | 补 `http2 on;` 并 reload |
| 页面样式全丢 | `assets/` 没传上去 | `curl -s -o /dev/null -w "%{http_code}" …/assets/style.css` | `deploy.bat` 会传 assets，检查是否有权限问题 |
| 站点打不开 / 502 | nginx 挂了或证书过期 | `sudo nginx -t`、`systemctl status nginx` | `reload`；证书过期跑 `certbot renew` |
| APK 下载很慢或中断 | 没开 `Accept-Ranges` | `curl -sI …/downloads/x.apk \| grep -i accept-ranges` | 补 1.1 第 ③ 条 `/downloads/` 段 |

## 5. 回滚（没有备份机制，所以更要说清楚）

现状：`deploy.ps1` **只上传、不删除**，所以不会出现「误删远端文件」。真正的风险是**传了一份有问题的页面上去**。

远端没有历史版本，回滚只能重传。所以每次部署前在本地留一个快照：

```powershell
robocopy "D:\WorkBuddy\KidsSafeDesktop\Website" "D:\_site_snapshot\$(Get-Date -f yyyyMMdd-HHmm)" /MIR /XD downloads /NFL /NDL /NJH
```

- `/XD downloads` 排除 250 MB 的安装包，快照只有 5 MB 左右
- 出问题了就把快照目录的内容传回去：

```powershell
scp -r "D:\_site_snapshot\20261105-2345\*" root@你的IP:/var/www/kids/
```

> `Website\Website.7z`（244 MB）是早期整站打包，**不要当备份用**，它比线上版本还旧。

## 7. 红线（儿童类产品，踩了代价远大于收益）

- 页面上任何「提升智商 / 治疗注意力 / 矫正」类功效表述，一律不写
- 不用「最」「第一」「国家级」等绝对化用语（广告法）
- 加任何第三方统计（百度统计、GA4、Umami）都算引入第三方 SDK，必须同步改 `privacy.html` 的 SDK 清单——否则和「无第三方追踪」的宣传自相矛盾。建议用自建 Umami（同一台服务器）
- 隐私政策、权限说明、实际 APK 三者必须一致
- 群里和页面上都别收集孩子的真实姓名、学校、照片
