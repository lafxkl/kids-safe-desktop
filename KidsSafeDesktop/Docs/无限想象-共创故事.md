# 无限想象 · 共创故事（从 Dreamloom 移植）

> 源项目：`D:\Downloads\Dreamloom`（华为云码道参赛作品，网页版「无限想象」睡前故事共创平台）
> 落地形态：原生 MAUI 页面（不是 WebView 套壳）

## 一、为什么用原生重写而不是塞 WebView

源项目是一份 1437 行的 `index.html` 加一个 Node 代理（`tts-proxy.js`，负责微软神经语音与跨域转发）。塞进 WebView 能最快跑起来，但会丢掉这个应用已经建好的四件事：

| 能力 | WebView 方案 | 原生方案 |
|---|---|---|
| 统一星星账本 | 孤立，需另建一套 | 直接进 `StarCenter`，与 19 款游戏、学习页同一账本 |
| 护眼模式 | 遮罩盖不住 WebView 内滚动区 | 全局遮罩天然生效 |
| 系统 TTS | 需 JS 桥接，安卓 WebView 的 `speechSynthesis` 支持并不稳 | 直接用 `Helpers/Tts.cs`，与故事屋同一套中文语音包 |
| 家长后台 / 隐私政策 | 数据在 localStorage，不参与任何合规声明 | 进 `Preferences`，可写进隐私政策 |

代价是代码量变大（约 1300 行 C#），但换来的是一致的产品行为。

## 二、保留了什么

### 1. 五个小伙伴的分工

| 角色 | 职责 | 在原版里的台词逻辑 |
|---|---|---|
| 💡 灵感火花 | 从孩子原话里抓元素 | 「抓到了：小兔子 · 森林 · 小小毛毯。主题：《…》」 |
| 🌌 场景星球 | 定场景与天气 | 「场景：森林，下着细雨。围绕同一个心愿展开。」 |
| 🧭 创作向导 | 排四步因果链 | 「逻辑线：A → B → C → D」 |
| ✨ 精修精灵 | 收束语气 | 「以『雨夜』收束，落到暖暖的睡意上。」 |
| 🔭 天赋瞭望 | 写入成长数据 | 「潜能已更新：想象力 +1 · 词汇 +1 · 表达 +1」 |

### 2. 四步因果链

写死的结构，也是提示词里的硬约束：

```
① 主角想睡觉，却被一个小困扰 / 小愿望牵住
② 出现一个小小的转折或求助
③ 用温柔的办法解决（主角必须主动参与）
④ 安心入睡
```

原版调试结论（写在其 README 与代码注释里）：**先让模型输出 outline，再写正文**，否则长篇中文叙事会中途崩逻辑。移植时把这条规则原样搬进了 `StoryLoomEngine.BuildAiMessages`。

### 3. 三条内置模板故事线

模板不是随机拼句，每条线各讲一件真实的小事：

| 触发条件 | 故事 | 在讲什么 |
|---|---|---|
| 神奇伙伴 = 迷路的小纸船 | 《X 给小纸船指路》 | 不盲从、先观察再行动：陪它看清桥和丝带，而不是推它一把 |
| 心情 = 怕黑 | 《X 认出了夜里的影子》 | 把不认识的影子认出来，恐惧就变小了 |
| 其余情况 | 《X 和 XX 的晚安约定》 | 入睡仪式：每说一句晚安就把声音放轻一点 |

此外，物品会按**真实用途**出场（热牛奶是喝掉、小饼干是收进盒子、围巾是围上），这条规则来自原版踩过的坑：模型容易把食物当衣物用。

### 4. 六维语言潜能

| 维度 | 每生成一个故事 |
|---|---|
| 想象力 / 词汇丰富 / 表达力 | 固定 +1 |
| 叙事结构 / 情感感知 | 60% 概率 +1 |
| 专注坚持 | 25% 概率 +1 |

上限 10，到顶不再涨。页面上不写「分数」，只写「随共创慢慢长」，也不做任何横向比较——这是刻意和孩子的发展规律对齐：3–8 岁的语言能力不该被量化排名。

## 三、改了什么（以及为什么）

| 原版 | 移植版 | 原因 |
|---|---|---|
| 微软 Edge 神经语音 + 8 种音色（需本地 Node 代理） | 系统 TTS，逐段朗读并高亮当前段 | 家庭网络不稳、代理要开电脑；系统语音装上就能用 |
| 逐字打字机效果 | 逐段淡入 + 「显示全文」 | 一段 60–80 字，逐字刷新在低端安卓机上掉帧 |
| `localStorage` | `Preferences` + `System.Text.Json` | 与星星中心、关爱中心同一套本机存储约定 |
| 大模型直连、Key 存 localStorage | 默认关闭，家长 PIN 后才可配置，Key 进 `SecureStorage` | 儿童数据不该默认外发 |
| 无奖励系统 | 每生成一个故事记 2 星，每天最多 3 个故事记星 | 与全应用奖励口径一致，同时防刷 |
| 世界记录仅展示 | 同样展示最近 30 条，随成长数据一起清空 | 保持原版「看得见创作过程」的设计 |

## 四、隐私边界（写进代码也写进政策）

1. 默认路径：输入 → 本机模板 → 本机存储，**零网络请求**；
2. 家长开启「大模型故事引擎」后，才会把「孩子说的一句话 + 所选元素」发到家长自己填写的服务器；
3. API Key 存在 `SecureStorage`（Android Keystore / Windows DPAPI），失败时退化为应用私有目录的明文，并在文档中标注；
4. 成长数据不包含原始输入文本，只记「本次采纳了几个元素」的计数；
5. 页面上家长卡片的措辞是「孩子说的话会发到所填服务器」——不藏在「高级设置」里。

## 七、后补的三件（v1.17 补齐）

第一版留了三件没做，这一轮补掉了，做法和取舍记在这里。

### 1. 多音色 → 改成「声音风格」

真正换发音人做不到：一台设备的中文语音包通常只有一个，要多个音色只能接云端 TTS，那和「离线优先」直接冲突。

所以做的是 `Models/VoiceStyleData.cs` 里的四个预设，改的是**音高（Pitch）+ 段间停顿倍率（GapScale）**：

| 风格 | 音高 | 停顿倍率 | 听感 |
|---|---|---|---|
| 🌸 温柔姐姐 | 1.12 | ×1.25 | 轻、慢，句间留白多 |
| 🧓 慈祥爷爷 | 0.84 | ×1.45 | 低沉、很慢 |
| 🐣 活泼小伙伴 | 1.32 | ×0.82 | 清脆、走得快 |
| 📖 标准朗读 | 1.00 | ×1.00 | 系统原声 |

- 音高夹在 0.5–1.6，超出会明显失真（像快进的卡通音）。
- 停顿 = 节奏档位基础值（1100 / 520 / 150ms）× 倍率，再夹在 80–1800ms。
- **界面上如实写了「调的是音高和停顿，不是换配音演员」**，帮助中心也写了。不夸大，家长才不会以为点了没生效。
- `Tts.SpeakAsync` 加了第 4 个参数 `pitch`，降级到系统默认语音时同样保留音高。

### 2. 语音输入（Android，家长 PIN 开启）

`Platforms/Android/VoiceInput.cs` 走系统 `Intent.ActionRecognizeSpeech`，不是自己录音：

- **不申请 RECORD_AUDIO**。麦克风权限由系统识别器自己持有，我们的清单里没有录音权限——这本身对儿童桌面就是一条可验证的承诺。
- 取消即返回 null，不留音频文件。
- 没有识别器的设备（多数 Windows 机器、个别定制安卓）直接隐藏麦克风按钮，而不是点了没反应。

一个必须处理的冲突：识别界面是另一个 Activity，本应用会进 `OnStop`，而 `OnStop` 里有「防退出」的自动拉回前台——两者会打架，识别界面刚弹出来就被盖掉。处理方式是启动识别前调 `MainActivity.SuppressAutoReturnFor(60s)`，`OnResume` 会自动解除。

默认关闭，第一次点 🎤 要家长过 PIN（`ISettingsService.VerifyPin`），与「大模型生成」同一套规矩。

### 3. 故事图片卡导出

没有引入 SkiaSharp（APK 已 110MB+，为一张卡再加十几 MB 不划算），而是：

1. `Helpers/StoryCardExporter.BuildCard` 用正常 XAML 排出卡片（渐变夜空底、标题、正文、寓意、落款）；
2. 放进 `Pages/StoryCardPage` 预览页里渲染；
3. 调 MAUI 10 的 `View.CaptureAsync()` 截图成 PNG，存缓存目录，走系统分享面板。

关键约束：**`CaptureAsync` 只能截已经渲染在界面上的 View**，所以不能后台静默生成。既然躲不过去，就做成预览页——孩子看到的就是要发出去的那张图。

另外给了「📋 复制文字」的退路：有些聊天软件会把长图压得看不清。

图片只落在缓存目录，孩子没点「分享」之前不往相册写任何东西；清理缓存即消失。

### 仍然没做

- **iOS / Mac 的语音输入**：本项目只出 Android 与 Windows 两端。
- **Windows 的语音输入**：没有等价的系统识别入口，`VoiceInput.IsSupported` 返回 `false`，按钮不显示。
- **无限想象的故事导出图片卡**：目前只有星夜故事屋有（`StoryCardPage` 是通用组件，接过去很快，但先看这条路径在真机上稳不稳）。
