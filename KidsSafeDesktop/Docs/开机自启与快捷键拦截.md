# 开机自启 / 常驻守护 / 系统快捷键拦截

> 目标：孩子开机就在儿童桌面里，且不容易用「任务管理器 / 快捷键 / 设置 / 卸载」跑出去；
> 家长随时能关掉。
>
> 本文写清楚**每一端能做到什么、做不到什么、为什么**。做不到的部分不写「已实现」，
> 是为了避免上线后被当成 bug 反复排查。

---

## 一、能力矩阵（先看这张表）

| 能力 | Windows | Linux（kiosk 会话） | Android |
|---|---|---|---|
| 开机自启 | HKCU `Run` 值 `--kiosk-guard`（安装器默认勾选） | XDG autostart 或 systemd `--user` 单元（二选一） | `BOOT_COMPLETED` 广播 + 前台服务 |
| 被杀后自愈 | 守护进程：非 0 退出 3 秒后重启，连续 5 次「起来就死」放弃 | systemd `Restart=always RestartSec=2` | 前台服务 `START_STICKY` + 每分钟心跳闹钟 + 无障碍连接时互拉 |
| 屏蔽 Win 键 | ✅ 低级键盘钩子 | ❌ 无此概念（无面板/无 WM 更彻底） | ❌ 无此概念 |
| 屏蔽 Alt+Tab | ✅ 钩子 | ⚠️ X11 下 `XGrabKey` 可抢；Wayland 不行 | ⚠️ 只能「切走立刻拉回」/ 屏幕固定 |
| 屏蔽 Alt+F4 | ✅ 钩子 | ⚠️ 同上（且本应用拒收关闭事件） | — |
| 屏蔽 Ctrl+Shift+Esc（任务管理器） | ✅ 钩子 + `DisableTaskMgr` 策略 + 盯进程 | ⚠️ X11 可抢；Linux 无「任务管理器快捷键」这一说 | — |
| 屏蔽 Ctrl+Alt+Del | ❌ 系统安全序列（SAS），任何用户态程序都收不到 | ❌ VT/内核级，应用层拦不住 | ❌ 电源键菜单同理 |
| 兜底措施 | 禁用任务管理器 + 从安全桌面返回后抢回前台 | 会话裁剪（不启桌面环境）+ `DontVTSwitch` | 默认桌面 + 自动回前台 + 无障碍拦截设置/商店/卸载 |
| 防卸载 | 安装器卸载需要 UAC/管理员 | 包管理器卸载需要 sudo | 设备管理员激活后系统卸载界面要求先取消激活 |

**一句话结论**：Windows 靠钩子拦按键，Linux 靠「根本没有别的窗口」，Android 靠「默认桌面 + 无障碍 + 设备管理员」。
三端都不指望「拦住 Ctrl+Alt+Del」，那是操作系统留给使用者的最后出口，也是家长自己要用的出口。

## 二、Windows

### 2.1 自启 + 守护（`WindowsStartup`）

位置：`KidsSafeShared/Platforms/Windows/WindowsStartup.cs`

写的是 **HKCU** `Software\Microsoft\Windows\CurrentVersion\Run`，值名 `KidsSafeDesktop`：

```
"C:\Users\<user>\AppData\Local\Programs\KidsSafeDesktop\KidsSafeDesktop.exe" --kiosk-guard
```

为什么不是直接起主程序：直接起主程序，被任务管理器结束一次就永久失效——
而「结束进程」恰好是孩子最先学会的一招。带 `--kiosk-guard` 时，同一个 exe
在**建窗口之前**就进入守护循环：

```
守护启动
  ├─ 已有守护在跑？（命名互斥体）→ 直接退出
  ├─ 上次家长点过「退出」？（.guard_off）→ 消费标记，退出
  └─ 循环：
       拉起主程序 → 等它退出
         ├─ 退出码 0（家长在面板点「退出」）→ 守护结束
         ├─ 检测到 .guard_off → 消费标记，结束
         └─ 非 0 → 3s 后重启；存活 <20s 记为「起来就死」，连续 5 次放弃
```

- 日志：`%LOCALAPPDATA%\KidsSafeDesktop\guard.log`
- 标记：`%LOCALAPPDATA%\KidsSafeDesktop\.guard_off`（家长主动退出时写；守护读到即退出）
- 安装器：`Installer/KidsSafeDesktop.iss` 的 `autostart` 任务，卸载时删该值
- 家长面板：`家长设置 → 🖥 系统守护（PC） → ① 开机自动进入儿童桌面`

> ⚠️ 不要把它改成「计划任务每分钟检查一次」：GUI 子系统程序每分钟被拉起一次，
> 虽然看不到窗口，但会让笔记本的风扇和电池统计变得很奇怪。守护进程是单进程常驻，更干净。

### 2.2 快捷键拦截（`WindowsKioskService.HookProc`）

`SetWindowsHookEx(WH_KEYBOARD_LL)` 全局低级键盘钩子，命中即 `return 1`（吞掉）：

| 组合键 | 用途 |
|---|---|
| Win（左/右） | 开始菜单、Win+R、Win+E、Win+X、Win+Tab |
| Alt+Tab / Alt+Shift+Tab | 切换窗口 |
| Ctrl+Alt+Tab | 方向键切换窗口 |
| Alt+Esc | 直接切到下一个窗口（绕过 Alt+Tab） |
| Alt+F4 | 关窗口 |
| Ctrl+Esc | 开始菜单 |
| Ctrl+Shift+Esc | **任务管理器** |

**拦不住的**：Ctrl+Alt+Del（SAS）。它由 winlogon 在安全桌面里处理，键盘钩子属于
用户态、在它之后，物理上收不到。所以这里不假装能拦，而是做两件事缓解：

1. `DisableTaskMgr`：进了安全桌面也点不出任务管理器；
2. `WindowsForegroundGuard`：轮询 `OpenInputDesktop`，一旦从安全桌面回到普通桌面，
   立刻把儿童桌面抢回前台（`AttachThreadInput` + `SetForegroundWindow`）。

Win+L 在策略生效后同样失效（`DisableLockWorkstation`）。

### 2.3 任务管理器三层拦截（`WindowsSystemPolicy`）

| 层 | 做法 | 覆盖场景 |
|---|---|---|
| ① 键盘 | 钩子吞 Ctrl+Shift+Esc | 最常用路径 |
| ② 策略 | HKCU `...\Policies\System`：`DisableTaskMgr=1`、`DisableLockWorkstation=1`、`DisableChangePassword=1` | 任务栏右键、Win+R、Ctrl+Alt+Del 菜单 |
| ③ 进程 | 前台守护 1 秒轮询 `taskmgr`，发现即 `Kill` | 策略被组策略覆盖 / 系统版本不认 |

**可逆性是硬要求**：这些策略键是**持久**的，进程崩了不会自己消失，
用户会得到一台「任务管理器永远打不开」的机器且找不到原因。所以：

- 写入前把原值抄到 `%LOCALAPPDATA%\KidsSafeDesktop\policy_backup.txt`
  （格式 `值名<TAB>原值`，原本不存在则记 `__absent__`）；
- `ExitAppAsync` / `ProcessExit` / `AppDomain.UnhandledException` 三处都还原；
- **启动自检**：`App` 构造时若发现备份文件还在（= 上次异常退出），先还原再重新 apply。

手工恢复（万一）：

```bat
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System" /v DisableTaskMgr /f
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System" /v DisableLockWorkstation /f
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System" /v DisableChangePassword /f
```

## 三、Linux

### 3.1 自启与自愈（`core/startup`）

两条路，**互斥**（同时开会起来两份全屏窗口互相抢焦点）：

| 方式 | 文件 | 能力 |
|---|---|---|
| A. XDG 自启 | `~/.config/autostart/kidssafe.desktop` | 登录拉起一次，没有崩溃重启 |
| B. systemd 用户单元 | `~/.config/systemd/user/kidssafe-guard.service` | `Restart=always`，被杀 2 秒后回来 |

B 的单元内容要点：

```ini
[Unit]
Description=儿童安全桌面（守护）
StartLimitIntervalSec=0        # 默认「10 秒 5 次就放弃」对儿童桌面等于没有守护
After=graphical-session.target

[Service]
ExecStart="/usr/local/bin/kidssafe"
Restart=always
RestartSec=2
Environment=KIDSSAFE_KIOSK_SESSION=1

[Install]
WantedBy=default.target
```

- 只 `systemctl --user enable`，**不 `--now`**：当前这个实例还活着，`--now` 会起第二份；
  本次会话的守护由 `kidssafe-session` 的 `while :; do ... done` 循环负责。
- 没有 systemd 用户实例（容器、精简系统）时自动退回 A，并在家长面板写明原因。
- 家长面板：`家长设置 → 系统守护 → ① 登录自启 / ② 自动重启`

检查：

```bash
systemctl --user status kidssafe-guard.service
journalctl --user -u kidssafe-guard -n 50
```

### 3.2 快捷键（`core/hotkeyguard`）

**X11**：`XGrabKey` 把组合键独占，事件只投给本进程，窗口管理器收不到。
已抢：Alt+Tab、Alt+Shift+Tab、Alt+F4、Alt+Esc、Ctrl+Esc、Ctrl+Shift+Esc、
Ctrl+Alt+Tab、Super（左右）。每组都连带 `NumLock`/`CapsLock` 变体一起抢
（否则按一下 CapsLock 就绕过去了）。

两个必须知道的限制：

1. 普通桌面里 Alt+Tab 已被 KWin/Mutter 先 grab，我们拿到的是 `BadAccess`（静默跳过）；
   所以这招在**没有窗口管理器的 kiosk 会话**里最有效——那时本来也没人抢。
2. `Ctrl+Alt+Del`、`Ctrl+Alt+F1..F12`（VT 切换）由 X 服务器自己处理，抢不到。
   要堵 VT 只能在 `xorg.conf` 里加（需要 root）：

```
Section "ServerFlags"
    Option "DontVTSwitch" "true"
    Option "DontZap" "false"
EndSection
```

**Wayland**：没有这个能力。协议里不给应用抢全局快捷键，连读全局按键都做不到。
Wayland 下唯一的锁是**会话裁剪**：`kidssafe-wayland-session` 用 `kwin_wayland` 或 `cage`
起一个只有本应用的会话，不加载 plasmashell、关掉 KWin 的总览手势。

> 设计取向：不在 Linux 上假装复刻 Windows 的按键钩子。可靠性来自会话裁剪，
> 不来自应用内的小动作。面板上的开关在 Wayland 下会显示「会话裁剪」而不是「已抢占」。

## 四、Android：对照「阳光守护」的运行方式

阳光守护这类产品在普通应用权限下（无 root、非设备所有者）靠的是同一套组合拳，
我们逐条对上了：

| 阳光守护的做法 | 本项目实现 | 文件 |
|---|---|---|
| 常驻前台服务 + 通知 | `KioskGuardService`：`START_STICKY`、通知重要性 Low（不吵）、切任务卡片后 2 秒重启 | `Platforms/Android/Guard/KioskGuardService.cs` |
| 心跳/闹钟互拉 | `AlarmManager.SetAndAllowWhileIdle` 每分钟一次（不需要精确闹钟权限） | `KioskGuard.cs` |
| 开机自启 | `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` → 起服务 + 拉起主界面 | `KioskBootReceiver.cs` |
| 无障碍监控前台应用 | `KioskAccessibilityService`：命中设置/安装器/商店/权限弹窗 → `GLOBAL_ACTION_BACK` + 拉回儿童桌面 | `KioskAccessibilityService.cs` |
| 设备管理器防卸载 | `KioskDeviceAdminReceiver`（只声明 `force-lock`，不碰擦除数据） | `KioskDeviceAdminReceiver.cs` |
| 默认桌面替换 | 已有：`CATEGORY_HOME` + `RoleManager`（家长面板 ③） | `AndroidKioskService` / `MainActivity` |
| 切走立刻回前台 | 已有：`OnStop → MoveToFront`（家长面板 ①） | `MainActivity` |
| 屏幕固定 | 已有：`startLockTask`（家长面板 ⑤） | `MainActivity` |
| 电池优化白名单 | 已有（家长面板 ④） | `AndroidKioskService` |
| 厂商自启动权限 | **代码申请不到**，只能提示家长去「手机管家 → 自启动管理」放行 | 家长面板文案 |

### 家长需要按顺序做的授权
1. ⑥ 后台常驻守护（默认开，无需操作，只需要允许通知）
2. ④ 忽略电池优化
3. ① 离开后自动回到儿童桌面（默认开）
4. ② 「显示在其他应用上层」——Android 10+ 后台拉前台要靠它
5. ③ 设为默认桌面
6. ⑦ 无障碍守护（**必须手动开**，系统不允许应用代开）
7. ⑧ 设备管理员（**必须手动确认**）

### 拦截名单与「临时放行」

拦截（→ `GLOBAL_ACTION_BACK` + 拉回儿童桌面）：系统设置、各厂商安装器/卸载确认框、
应用商店（Play、华为、荣耀、小米、OPPO/vivo、应用宝、360、百度）。

**刻意不拦**：权限弹窗（`com.android.*.permissioncontroller`）。本应用自己要在启动时申请
通知权限、家长要授予「显示在其他应用上层」，拦了会把自家授权流程按掉，
症状是「点了允许但没生效」，极难查。

**临时放行**：家长从面板点 ⑦/⑧ 时，`OpenSettings` / `Request` 会先调
`AndroidHooks.SuppressAutoReturnFor(5 分钟)`。守护看到
`MainActivity.AutoReturnSuppressed` 就直接放行——否则家长刚打开设置就被自己弹回来，
永远授不了权。这个窗口只能由家长面板触发，孩子无法自己打开。

### 上架注意

`KioskGuardService` 用的是 `specialUse` 前台服务类型（家长控制没有更贴切的类型）。
Google Play 要求在「应用内容 → 前台服务」里申报用途；清单里没有写
`<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE">`，
若审核明确要求再补（补的时候用 `tools:node="merge"` 合并，别重复声明整个 `<service>`）。

### 安卓侧管不住的情况（如实说明）

- 长按电源键 → 关机/重启：无障碍拿不到电源键；
- 安全模式启动：第三方应用全部不加载；
- 恢复出厂设置；
- 家长主动在系统设置里关掉无障碍/撤销设备管理员（这是设计上必须留的出口）。

## 五、验收清单

### Windows

1. 安装时勾选「开机自动进入儿童桌面」→ 重启 → 登录后自动全屏；
2. 任务管理器里结束 `KidsSafeDesktop.exe` → 3 秒内自动回来（`guard.log` 有记录）；
3. 按 Ctrl+Shift+Esc / Win+R / Alt+Tab / Alt+F4 / Alt+Esc → 全部无反应；
4. Ctrl+Alt+Del → 安全桌面能进（拦不住），但「任务管理器」点开提示被禁用；返回后儿童桌面自动回前台；
5. 家长面板「退出模式」→ 应用关闭且**不再被拉起**；重新登录后才再启动；
6. 强制关机重启后，任务管理器可正常打开（说明策略已还原）。

### Linux

1. 面板打开「① 登录自启」→ `cat ~/.config/autostart/kidssafe.desktop` 有 Exec；
2. 打开「② 自动重启」→ `systemctl --user is-enabled kidssafe-guard` 为 `enabled`，
   且 autostart 文件已被删除（互斥）；
3. X11 kiosk 会话里按 Alt+Tab / Ctrl+Shift+Esc → 无反应（`kidssafe.log` 有 `[hotkey] 已抢占 N 个组合键`）；
4. Wayland 会话下面板显示「会话裁剪」而不是「已抢占」（这是正确行为，不是 bug）。

### Android

1. 冷启动 → 通知栏有「儿童桌面守护中」，`adb shell dumpsys activity services | grep KioskGuard` 可见；
2. 最近任务里划掉本应用 → 几秒后自己回来；
3. 打开系统「设置」→ 自动退回儿童桌面（无障碍开着时）；
4. 卸载 → 系统提示需先取消设备管理员；
5. 关机重启 → 不用手动点，自动回到儿童桌面（部分 ROM 还需厂商「自启动」放行）；
6. 家长关掉 ⑥ → 服务停止且**不再被心跳拉起**。

### 彻底关闭（家长自己也要能关）

- Windows：面板关「开机自启」→ 删除注册表 Run 值；面板关「屏蔽任务管理器」→ 策略按备份还原。
- Linux：面板关两个开关 → 删 `~/.config/autostart/kidssafe.desktop` 与
  `systemctl --user disable --now kidssafe-guard`（再删单元文件）。
- Android：面板关 ⑥ → 停服务；⑦ 去系统设置关无障碍；⑧ 解除设备管理员 → 之后可正常卸载。

## 六、给后续维护者

- 三端的「守护」都是**同一个 exe/二进制**的另一个模式，不是第二个程序：
  Windows 是 `--kiosk-guard` 参数，Linux 是 systemd 直接跑主程序，Android 是同 APK 里的 Service。
  这样增量更新（只换 dll）不会因为「守护程序没更新」出现版本错配。
- 任何持久化改动（注册表策略、自启文件、系统设置）都必须有**对应的还原路径 + 启动自检**。
  崩溃一次就留在用户机器上的副作用，最终都会变成差评。
- 新增拦截项时先问一句「拦不住会怎样」，能在文档里写清楚的就别在代码里假装拦住了。
